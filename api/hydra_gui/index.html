Crate hydra_gui 

Source
Expand description

Hydra’s windows: egui, drawing each character from its session.

Each character has a play window: one command input, and its widgets – the story, the streams, the room, the vitals, the clocks, the injuries, the effects and the rest – held by windows inside it that drag, resize, snap to a grid and sit in drawers, the layout kept by the character’s name, and keys bound to what they do (keys). The hub lists every character, brings each one’s window up, and launches the roster’s characters and new logins. What a window shows is hydra-ui’s, projected without a toolkit; this draws it.

Modules§

badge
Hydra’s badge: the icon every one of Hydra’s windows wears, the hub, a play window, Settings and the rest, however Hydra was started, and the tray’s. Built in, and read once.
bar
A progress bar: it fills across or upright (or as an orb, a ring, or a panel under its stat’s emblem), its height and width adjustable, with an overlay laid over it, and text inside it, outside it on any of the four sides, or none – the text numbers, a percent, a label, or any mix of them.

Functions§

opening
Call told with each stage of the windows’ opening, up to the first frame drawn, the next time they open.
run
Open the windows over sessions – the hub shown or hidden as open says, and each character’s play window it keeps – and run until the last closes, or the binary closes them once the run is over ([Sessions::close]). A character seated after opens its play window unless it was started headless or for the web. The hub’s requests run on runtime; layouts, presets, keys and pictures are kept in data, the data folder. Blocks the calling thread, which must be the main one.
