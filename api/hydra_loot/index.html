Items as things, not as ids.

The game names an item by an id that lasts one session: a relog gives everything carried a new id, and a box comes back from the locksmith pool as a new object. What was found, appraised, carried and sold is one thing throughout, so the ledger keeps an item as one row and the ids it has worn as its item_ids, each with when it was first and last seen.

  • ascension: the creatures whose searches count toward ascension gemstones and dust, from the list the crate carries.
  • finds: the rare finds reported: gemstones, dust, keys and locks, legendary treasures, each against the searches it took.
  • identity: the keeper, one a character: an id in, the item row out, made on first sight.
  • relog: the inventory before a logout and after the login walked together, so each item’s old id becomes its new one.
  • pool: a box dropped at the locksmith pool and the box handed back, linked by name and order.
  • recorder: each loot event the model read, written as rows against its items.
  • task: the recorder on a session, and the inventory asked of the game at login and before a quit.
  • catalog: the reports named, for a window that lists them.
  • report: lines from rows, and .loot.

Modules§

ascension
The creatures whose searches count toward ascension gemstones and dust, from the list kept in data/ascension.txt: the grounds’ own, and the Onslaught’s invaders apart, since whether those count is not settled.

The reports named, for a window that lists them: each with the words that ask for it and a line saying what it shows. Only the reports.
finds
The rare finds reported, each against the searches it took: ascension gemstones and dust off the listed creatures, keys and locks and legendary treasures off any creature.
identity
The keeper: one a character, holding which item row each id of the session names, and writing both as they are first seen.
pool

recorder
Each loot event the model read, written as rows against its items.
relog
The inventory before a logout and after the login, walked together.
report
.loot: what was found and what it came to, from the ledger.
task
The recorder on a session: loot events heard on the session’s thread, handed to a thread of their own that writes them, so no game thread waits on the disk.
