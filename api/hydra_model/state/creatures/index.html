Module creatures

Expand description

The creature registry: every creature the feed has shown, keyed by exist id, with the current room’s roster and what combat did to each.

The registry is the id-keyed store, the room roster and housekeeping; apply is the consumer that turns ChunkFacts into creature state. instance is one creature; body is where a wound lands.

§Where the registry is fed from

A creature is registered from a bolded <a exist> in room objs whose id has a <crtrStatus> vouching for it in the same body. On the wire the tag precedes the link it describes.

The frames arrive the other way round. The parser emits the Frame::Component first and the tags its body carried after it (parser/dispatch.rs, inline_paired: “After the frame, in wire order”). So the pairing runs link-first: the room objs body’s bold links are held in Creatures::apply_room_objs, and each Frame::CreatureStatus that follows claims its link in Creatures::note_status. Either way, a creature is registered when a tag vouches for its link. <nav> and each room objs refresh clear the roster first.

Two choices, both toward keeping a fact:

  1. A <crtrStatus> for a creature already registered is applied at once, not held for the next room refresh, so a standalone tag for a known creature does not lag until the next room objs. The roster-marking a refresh does is done on both paths.
  2. A combat event that names a creature by exist id registers it if the feed has not yet (Creatures::ensure), rather than skipping an unknown id and losing the damage. An attack on it is proof it exists and is here – unless the feed showed it leave in the same chunk: the facts are applied as the chunk closes, and tell of before it left.

§Bounds

MAX_SIZE instances; housekeeping every HOUSEKEEPING_INTERVAL server seconds drops creatures unseen for CLEANUP_MAX_AGE, never one on the live roster or the roster just replaced (the mid-refresh shelter). Evictions and refusals are counted.
