hydra_model::state::combat

Module parse 

Source
Expand description

The combat state machine over one chunk.

Turns a prompt-bounded chunk into attack events in one pass over the lines, with the branches in a fixed order – because that order IS the behaviour: the status handler runs before the flare branch so a flare-and-status line files on the flare it announces; the switcher runs before the outcome branch so an outcome lands on the target it names; the attack branch runs last so a same-line outcome belongs to the event the line opens. Any other order misfiles a line.

Each branch is a method on cursor::Cursor in its own module, split by what the branch handles rather than by size:

ModuleHandles
cursorthe working state, the pool, the predicates
factsstatuses, spell losses, UCS
flaresflare announces, sequence and assault brackets
switchtarget switching
rollsroll lines, outcome lines
attackinitiations, and every claim they make
damagedamage, the coup, the crit lookahead
finishthe hold, the orphan sinks, the emit

§What is not here

  • Settings. Everything is tracked, and the recorder is always subscribed.
  • Ingestion provenance. A chunk belongs to one session’s one connection by construction.
  • Room components. They never reach the chunk; they are routed to the room model by the stream layer.
  • The registry. Applying these events to creatures – persisting them, the death sweep and position recovery – is the consumer above this one (creatures/apply.rs). LossCause::Death is decided from this chunk’s kills alone.

§A second-person status target

A status def that captures a second-person target (You are stunned! through a (?<target>...) group) would otherwise go to a name lookup and be dropped by the registry. It is emitted here as Subject::Us (facts.rs), so nothing is dropped.
