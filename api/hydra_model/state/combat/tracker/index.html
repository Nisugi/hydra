The combat consumer: what survives between chunks, and the entry point.

The cross-chunk state of the combat parse, and its one real job: feeding a prompt-bounded chunk to the state machine. Buffers, worker threads and settings stores are plumbing the chunk mechanism and the session already own.

§Three facts cross a chunk boundary

FieldWhy it must survive the prompt
held_cast“You gesture at X.” ends a chunk; the spell’s result opens the next. Held for ONE chunk, then superseded or emitted as itself.
held_pre_flaresA bow’s dispel fires on the NOCK and resolves before “You fire” prints – in the next chunk.
active_assaultA flurry’s rounds arrive over several chunks; the opener named the only target they can strike.

The death watch (a creature an event touched, watched until a room refresh flags it dead) belongs to the creature registry. Position recovery is reset at the top of every chunk and is therefore chunk-local, on the cursor.

§No settings

Damage, wounds, statuses, UCS and the event payload are always tracked: a config option with only one sensible value is not an option, and a wrong gate leaves a crit-shaped hole in what is emitted.

§The crit tables are a handle, not a global

crit.rs holds CritTables behind an Arc and forbids a static, for the reason multi-session depends on. So the tracker is handed its tables by whoever built the GameState – CombatTracker::set_crit_tables – and without them the crit lookahead is skipped and every Hit carries crit: None. A test that asserts crits sets them; a session sets them once.
