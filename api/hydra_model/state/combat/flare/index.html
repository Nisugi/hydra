Module flare 

Source
Expand description

Flare announce lines: weapon scripts, enchants, GEFs, flourishes.

Reads the flare family. Each def carries three flags the state machine routes on:

  • damaging – a damage line is expected to follow; a buff flare (acuity, tailwind) never produces one;
  • aoe – false when the flare is single-target even if its parent is not;
  • spawns – the flare casts an imbedded spell as a SEPARATE attack (Blink), so what follows in the chunk is its child.

Timing is not declared. Whether a flare resolves before its swing (dispel gloves) or after (most) is positional: a flare seen with no open attack event is held and claimed by the next swing. That is the state machine’s job; this only says what the line is.

§The flaring weapon is a link after Your

A 2p flare names its weapon as a link (Your <a exist="..." ...>), and the id is the join key for claiming pre-flares by weapon. Written by hand (defs::HAND_PORTED): the weapon is the first link whose run follows the text Your .

§The mirror table, after the main flares

The main flare table misses most custom and festival flare texts, purified metals, lore-flare repeats, weapon and armor scripts, Covert Arts poisons, the _GS jewel properties and ensorcell. A second table covers them: family flare_mirror (data/combat_flare_mirror.tsv, generated by tools/extract_flare_mirror.rb), read only when no main flare matches. A row that reuses a main flare’s name carries that flare’s flags, so a custom acid text is an acid flare. Six rows are left out: ensorcell’s benefit and the spirit animal’s prefix are lines of a proc a main flare already counts, and read here too each proc would count as two flares (the extractor’s NOT_PORTED). Ensorcell’s benefit is read into its flare instead, as the flare’s kind (parse/flares.rs).

Not on an attack or a damage line. Three mirror rows re-read a line the attack and damage grammar own: the Wither lore benefit is the wither initiation, the flaming aura’s lash is flaming_aura, and Sanguine Sacrifice’s “X suffers an additional N damage!” is a bleed tick (tests/combat_flare_mirror.rs). Read as a flare as well, the attack would claim its own announce as a pre-flare, and the tick would be counted twice – once as the flare’s inline damage and once as the damage line – as the replay blob weapon_cast 47a49e78552be40a shows. So a flare_mirror row never classifies a line that AttackLine or DamageLine reads.
