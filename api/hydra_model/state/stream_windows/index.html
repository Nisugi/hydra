What a stream’s text does when its window is closed: the wire’s own rule, read off <streamWindow ifClosed= styleIfClosed=>.

§The question this answers

When a stream arrives with an ifClosed= attribute, that attribute says what to do with the stream’s text if its window is closed. It is the whole of this problem, in four lines:

<pushStream id="speech"/><preset id='speech'>You <a ...>say</a></preset>, "Yep."
<popStream/>
<preset id='speech'>You <a ...>say</a></preset>, "Yep."
<prompt time="1790052928">&gt;</prompt>

The same sentence twice: once inside the speech stream, once in the main window. A renderer that shows both prints everything the character says twice.

That is not a defect in the game. speech is declared ifClosed='', and the protocol’s documentation says what that means: “The stream is a duplicate – the server also sends the same line to main, so the closed window’s copy drops harmlessly”. The duplicate is the wire keeping a promise to a client that has a speech window open. A client without one is supposed to drop the copy.

§The four behaviours, MEASURED

The protocol names four. All four are here in real traffic – census over 208 recorded sessions, 157,220 <streamWindow> tags:

Route is UNVERIFIED. The documentation cites voln → thoughts → main-as-thought and no recorded character declared one, so it is implemented from the documentation and labelled rather than claimed. It is also the only behaviour that chains, which is why Windows::route is written as a loop with a visit-set rather than a match.

ambients inverts the usual shape – ifClosed absent, styleIfClosed present and empty – which the documented table does not name. Read here as Closed::Main: an empty style is no style, and falling through unstyled is what the Unspecified row does anyway.

§Why ifClosed='' and a missing ifClosed cannot be one case

They mean opposite things – drop the text, versus show it in main – so this module lives or dies on telling them apart. Attrs is Vec<(String, String)> (frame.rs), so an empty value survives as Some("") and an absent one is None. VERIFIED against the parser: speech reads Some(""), logons reads None.

Collapsing them – attrs.get("ifClosed").unwrap_or_default() – would make every Unspecified stream drop its text, losing death and logons entirely. Absent is not empty.

§This decides routing; it does not decide windows

Whether a window is open is a frontend fact, so it is a parameter rather than state here. streams.rs keeps the same line: a map of buffers and a routing rule, with layout left to the UI. This module adds the second half of that rule – the part that needs to know what the window would have been for.
