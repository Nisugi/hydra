The ten statistics, and the classifier that reads an info line.

A closed vocabulary gets typed named fields; these are ten of them, plus the four scalars info carries alongside.

§Three columns, and the wire sends two or three of them

info prints two value columns and info full prints three:

                Ascended (Bonus)  ...  Enhanced (Bonus)          <- `info`
    Strength (STR):   115 (32)    ...  115 (32)

       Normal (Bonus) ... Ascended (Bonus) ... Enhanced (Bonus)  <- `info full`
    Strength (STR):  110 (30)    ...  115 (32)    ...  115 (32)

Both are read by one rule whose FIRST column is optional, so a 2-column line matches with normal absent. That is worth stating because it looks like a layout change that would break the reader, and it does not: both forms are tested.

So normal is only known after info full. Option per column, not one Option for the row.

§Enhancement is marked by BOLD, not by arithmetic

The wire bolds an enhanced number:

   Intuition (INT):    98 (24)    ...  <pushBold/>106<popBold/> (<pushBold/>28<popBold/>)

MEASURED through the parser – that line is five frames, only the last carrying ends_line:

bold=0 ends=false "   Intuition (INT):    98 (24)    ...  "
bold=1 ends=false "106"
bold=0 ends=false " ("
bold=1 ends=false "28"
bold=0 ends=true  ")"

A plain stat line is ONE frame with ends_line=true. So:

  • Reassembly is the consumer’s job – see state.rs’s pending, whose doc records that this same split once printed a worn inventory down the screen. A classifier may not assume one frame is one line.
  • bold_depth is the enhancement signal, available without a regex. Nothing has to infer enhancement by comparing columns; the wire says so.

StatLine::classify takes the reassembled text because that is what a classifier is (stateless, one line in, typed answer out). The bold runs are carried separately, by StatLine::classify_with_bold, for the caller that has them – bold is in the FRAMES, not in the joined line, so a classifier given only text cannot recover it.
