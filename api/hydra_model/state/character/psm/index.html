The PSM tables: an open set.

The five categories – cman, feat, armor, shield, weapon – each print a table of mnemonics and ranks. What each costs, and whether one can be used now given the ranks, the gauges and the effects, is cost.

§Why this is a BTreeMap where skills is an enum

Typed named fields are for closed vocabularies, and a map with is_known for open ones. The 46 skills are closed: the game has printed the same 46 for years. The PSMs are not: there are 80 combat maneuvers, 33 feats, 33 shield, 24 weapon and 11 armor specializations today, and Simutronics adds to them.

So a mnemonic Hydra has never heard of must still be stored and reported, not dropped. Silently discarding unrecognised names would lose a PSM the game added.

§The table, MEASURED

Cut from a recorded session and committed as psm_list.xml. The command was cman list:

  Skill                Mnemonic        Ranks Type           Category        Subcategory
  -------------------------------------------------------------------------------------
  Acrobat's Leap       acrobatsleap    0/1   Passive
  Combat Focus         focus           5/5   Passive
  Disarm Weapon        disarm          5/5   Setup          Warrior Guild

§Bold means KNOWN, not maxed

The finding that shapes this file. MEASURED across the capture’s 27 rows (this said 29; tests/psm_list.rs:104 records the recount):

BoldedRanks seen
yes (9 rows)1/1, 2/2, 3/3, 3/5, 4/5, 5/5 x4
no (18 rows)0/1 x2, 0/2 x2, 0/5 x14

Every bolded row has ranks > 0; every unbolded row is exactly 0/n. Hamstring 4/5 is bolded and not maxed, which is what rules out the “bold = maxed” reading. The game bolds what the character has actually trained.

The fraction says the same thing. Both are read; bold is the same structural signal stats and skills already read, so this module takes it and checks it against the fraction – a disagreement would mean one of the two readings is wrong, and Hydra should find out rather than pick.

§Bold spans WRAP across rows

Unique to this table among the fixtures. The wire emits <popBold/><pushBold/> mid-line, so one bold span closes and the next opens inside a single row’s text:

<popBold/>  Combat Movement      <d ...>cmovement</d>       5/5   ...

A consumer that reset bold state at ends_line would mis-attribute every row after the first. The parser tracks bold_depth across frames, so this is handled – but it is the reason the fixture exists rather than a hand-written table.

§The mnemonic is a link, not plain text

Each sits inside <d cmd='cman HELP acrobatsleap'>acrobatsleap</d>. The parser strips the markup, so a classifier here sees the display text, and this file has no pattern for markup.

The mnemonic column is the PSM’s short name, the same one the cost table is keyed by. So the wire’s own column is the key, and no outside table is needed to read a table.
