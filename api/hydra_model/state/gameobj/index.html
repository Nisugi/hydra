What kind of thing is this? Type and sellable classification.

Classifies an object by name and noun over data/gameobj-data.tsv, which is compile-tested (tests/gameobj_patterns.rs) and committed.

§The matching rule, and the two fields that never fire

Match on name OR noun, veto on exclude, and an object may match several categories at once. MEASURED against the data, two of the four fields are dead:

FieldRowsRead?
name62yes
noun26yes
exclude23yes, as a veto
suffix2no
full_name0nothing to match

suffix carries ^(s)$ twice – plural matching for the furrier and skin categories – and is not read. full_name is declared by no row, so it cannot fire. Implementing a matcher for data that does not exist would be inventing behaviour.

§No memo cache

The scan is over compiled patterns held in one table, and a cache keyed by object identity would be per-session state in a crate that holds none – so a caller that needs it memoizes at its own layer, where the lifetime is obvious.

§Degrading rather than crashing

The table is include_str!-ed at compile time, so it cannot be missing – and a pattern that fails to compile is skipped rather than panicking, with ObjectTypes::skipped reporting how many. Nothing is dropped without saying so.
