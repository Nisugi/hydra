Struct StatusInfo

pub struct StatusInfo { /* private fields */ }
Expand description

Every indicator the game has reported, and whether it is active.

BTreeMap, not HashMap: iteration order is deterministic, which replay and snapshot tests depend on.

Set an indicator. Returns true if the value changed.

Forget one id, so it reads never reported again.

For a reconnect, and only for the statuses nothing re-states: the login burst re-declares every <indicator>, so those are kept (reconnect.rs), while afflictions.rs’s six have no indicator and would otherwise keep a belief forever.

pub fn is_known(&self, id: &str) -> bool

Whether the game has ever reported this id.

Distinguishes “reported inactive” from “never reported”, which Self::get deliberately collapses. After a reconnect an unreported indicator is unknown, and rendering it as a confident “no” would be a stale belief.

Forget everything reported.

For the reconnect path: a new generation has been told nothing yet, so every indicator returns to never reported rather than keeping a belief from a connection that has ended.

pub fn known(&self) -> StatusReading<'_>

Every indicator, as a three-state reading.

None is unknown: the game has not said. Some(false) is the game having said no.

§Why this exists beside the bool accessors

The typed accessors collapse those two, and they are what a caller reaches for – status.stunned() reads like a question with an answer. After a reconnect it answers a confident false for every indicator, because reconnect.rs clears the map and indicator is absent from the login burst (MEASURED: unanimous across all seven captured logins).

Code that casts on “not stunned” would act on a belief nothing supports.

The collapsing accessors are kept rather than replaced: for a renderer, “no icon” is the right treatment of both states, and forcing every display site through an Option would add noise where there is no decision to make. The rule: anything that ACTS reads this; anything that merely DISPLAYS may read the bool.
