Module match_index 

Source
Expand description

The first-word bucket index that makes matching 2,394 patterns per line affordable, and the one pattern Rust’s regex cannot compile.

§The index is exact, not an approximation

A pattern anchored ^Word can only match a line whose first word is Word, so bucketing by that word cannot lose a match. Patterns not so anchored go in a residual list checked on every line.

§Why buckets and not one RegexSet

A single RegexSet over all 2,394 patterns is slow at this scale: its lazy-DFA cache thrashes. Raising dfa_size_limit helps a great deal, but bucketing still won on most lines in a one-off comparison, and it is simpler than tuning a cache budget. Those comparison figures were not kept as a reproducible bench, so they are not quoted here.

Note on memory: a regex cache belongs to a Regex (or RegexSet) and is pooled per concurrently-matching thread, not per session. With the tables behind an Arc, the cost scales with worker threads, not sessions. The same holds for the 2,394 separate Regex values this code uses, whose aggregate cache footprint has not been measured.

§A set over the residual

The residual list (~195 unanchored patterns) was most of the cost when tried one by one. It sits behind one RegexSet with a raised DFA budget. Measured in release, warm, over every line of the 85 combat replay blobs: CritTables::parse went from 17-20us to 1.6us per call. The set only nominates; entry_matches still decides, so the veto is untouched. tests/combat_gate.rs compares the result with a full scan of all 2,394 entries on every real fixture line, beside tests/crit_index.rs’s synthesised ones.

§What is verified

tests/crit_index.rs compares the index against a full scan for every pattern it can turn into a literal matching line. 45 patterns cannot be literalised – they carry an unescaped (, ), |, {, } or $, or are unanchored – and the test asserts that skip count is exactly 45, so a pattern becoming unliteralisable is a visible change rather than a silent widening of the gap. (A pattern with escaped parentheses, such as ^Burn exposes the spine \(from the front\)., is handled; a character-class scan over the data would wrongly count it.)

The 45 remain checked by shape rather than by match: the loader compiles every pattern, and crit_parity.rs’s digest covers every field of every entry. Synthesising a line for a pattern whose language is not a single literal needs a regex-to-string generator, a larger thing than the gap it would close.

Measured shape (tests/crit_index.rs, which asserts each): 454 buckets, 195 residual, largest bucket 72.
