Crate hydra_table 

Source
Expand description

Hydra’s table: every character’s session in one host table, the roster and the teams it starts from, the accounts and their passwords, and Hydra’s own commands on each character’s command line. Whatever shows the characters (the desktop’s windows, the web page, a phone) seats them from here through the board (hydra_board).

Lich runs behind each character with the lich feature, on by default. A build without it runs no Lich, and .lich says so.

Modules§

account
Who to log in as: the character’s account and game from the roster, and the account’s password.
commands
Hydra’s own command line: every line that starts with the command symbol, . (hydra_session::claimant).
connector
The live connector: log in and open the game connection, once per connection the session asks for.
lich_command
.lich: the player’s own Lich for a character, switched on and off.
pages
A character’s own pages in the settings menu, from its settings file (hydra_session::settings_store): General, how it is shown as it starts on its own, the command symbol, whether creatures’ tags are shown (.targetid) and how container looks are sorted; Player log, how old days are kept (every feed is written); and Theme, the theme its window wears and its own accent; Travel, travel’s settings (hydra_travel::settings); and Fights, how its story shows fights, beside the page of every character’s (fights).
relay
.to <character> <command> and .all <command>: a line typed on one character and sent on another, or on every one.
reward_claim
The login reward claimed for the characters that have not had it: a login made for the reward alone, at the time the player set.
roster
Which account each character is on, and which game.
session
A character’s session made for its login, not yet running: its data folder’s store, its session log while sessions are recorded, its player log while one is kept, and the crit tables for its combat lines.
store_claim
The month’s store Simucoins claimed for the accounts on the roster.
table
The session table behind the windows: every character this process runs, started on the host, seated in the windows, and the hub’s requests answered.
teams
Teams: roster characters started together, each of its windows kept where it was put for that team.
