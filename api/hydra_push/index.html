Crate hydra_push

Expand description

The push relay: what lets a trigger on the desktop Hydra put a banner on a phone running HydraFE.

Apple takes pushes for an app only from whoever signs it, with that team’s key. The key cannot go inside Hydra, where anyone could take it, so it lives on a server of the author’s, and this relay hands each desktop’s alerts on:

desktop Hydra --HTTPS, sealed--> nginx --> hydra-push --HTTP/2, JWT--> Apple --> phone
  • POST /register gives a desktop its own token (desktops), asked for once, as the phone is paired.
  • POST /push, with that token, takes a phone’s device token and the alert, sealed by the desktop with a key only it and the phone hold. The relay never reads it: Apple is handed “Hydra” and the sealed bytes, and the app opens them on the phone (apns).
  • DELETE /register, with the token, forgets it.

Each desktop token and each phone is held to a rate (limit). Nothing but the hashes of the desktop tokens is kept.

Modules§

apns
Apple’s push service: one alert to one phone, over HTTP/2.
config
What the relay runs with: one TOML file, /etc/hydra-push/config.toml unless named on the command line.
desktops
The desktops that may push: each one’s token, given at /register, kept only as its SHA-256 in desktops.json in the state folder.
jwt
The provider token Apple asks of every push: a JWT, ES256, naming the key and the team, signed with the team’s key.
limit
How often anyone may ask: a bucket for each key – a desktop’s token, a phone, an address – that fills at a steady rate up to a burst.
serve
The relay’s endpoints, HTTP/1.1 on localhost behind nginx.
