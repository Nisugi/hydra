1//! [`LiveSource`]: the TCP+TLS [`ByteSource`], the transport a real login uses.
2//!
3//! # No test reaches a real host
4//!
5//! **No test in this workspace calls [`LiveSource::connect`] against a real
6//! host**, and none may: logging into the live game service is done by hand.
7//! One test calls it against a LOOPBACK listener in its own process
8//! (`tests/keepalive.rs`), to read back the socket options it sets -- nothing
9//! leaves the machine.
10//!
11//! # Async, and why
12//!
13//! Every await here is cancellable. A blocking `read` is not:
14//! `set_read_timeout` is a timeout, not a cancellation, and a 250ms stop is
15//! unreachable from inside one.
16//!
17//! # Three facts about the servers this relies on
18//!
19//! 1. **One write per message.** Two `write_all` calls can emit two TLS
20//!    records and this server does not tolerate a command split across them.
21//!    Encoded in [`ByteSource::write_all`]'s contract and honoured below.
22//! 2. **`native-tls`, not `rustls`.** eaccess negotiates TLS 1.2 static-RSA
23//!    key exchange (0x009c), which rustls refuses to implement. Verified by
24//!    packet capture.
25//! 3. **The game socket is not the eaccess socket.** A login connects to
26//!    eaccess over TLS for the handshake, then opens a *plain* TCP connection
27//!    to the game host and sends the key. This type is the second of those:
28//!    the session's byte source is the game stream, which is not TLS.
29//!    `LiveSource::connect_tls` exists for the eaccess half, and is reachable
30//!    only through the certificate pin (`eaccess/pin.rs`).
31//!
32//! The game stream has a second route: the WebSocket shim on 443
33//! ([`LiveSource::connect_shim`], `shim.rs`), which IS TLS -- verified TLS,
34//! unlike eaccess. It is the fallback when the game port is unreachable.
35

43/// Idle time before the kernel sends its first keepalive probe.
44///
45/// This low to stay ahead of idle reapers in the network path (load balancers
46/// and NATs that drop a connection quiet for too long).
47pub const KEEPALIVE_IDLE: Duration = Duration::from_secs(30);
48
49/// Time between probes once they start.
50pub const KEEPALIVE_INTERVAL: Duration = Duration::from_secs(30);
51
52/// How long sent data may sit unacknowledged before the kernel fails the
53/// socket. `TCP_USER_TIMEOUT`, Linux and Android only -- see
54/// `set_user_timeout` in this file for why it is only those two.
55///
56/// **120s, not something tighter.** A value known to work against these
57/// servers; 10s would drop a session over an ordinary mobile handover.
58///
59/// What it buys is the send-side twin of keepalive. Keepalive only probes an
60/// IDLE connection; once a command has been written and not acknowledged, the
61/// socket is not idle, keepalive stays silent, and Linux retransmits for
62/// `tcp_retries2` = 15 rounds before the write errors -- `tcp(7)` puts the
63/// default at a hypothetical 924.6 seconds, about 15 minutes. Not measured
64/// here: no test in this workspace may sever a real connection.
65pub const UNACKED_SEND_TIMEOUT: Duration = Duration::from_mins(2);

67/// A live connection: plain TCP to the game, or TLS to eaccess.
68///
69/// Two shapes rather than two types because they differ only in whether a TLS
70/// layer is wrapped around the same socket, and everything above them --
71/// read, single-write, shutdown -- is identical. Two types would be a trait
72/// with two implementors that never diverge: an abstraction with nothing to
73/// abstract over.
74///
75/// The third shape is the same game stream reached another way, when the game
76/// port cannot be: see `gemstone/shim.rs`.
77#[derive(Debug)]
78pub enum LiveSource {
79    /// The game stream. Plain TCP: the game host takes the key in the clear.
80    Plain(TcpStream),
81    /// The eaccess handshake. TLS 1.2, static-RSA, `native-tls`.
82    Tls(Box<tokio_native_tls::TlsStream<TcpStream>>),
83    /// The game stream through play.net's WebSocket shim on 443, over
84    /// verified TLS. The fallback when [`Self::Plain`] cannot connect.
85    WebSocket(Box<shim::ShimStream>),
86}

88/// Turn on TCP keepalive, so a half-open socket eventually fails a read.
89///
90/// # The failure this exists for
91///
92/// **A connection that is severed rather than closed never returns `Ok(0)`.**
93/// Measured: putting the machine into airplane mode mid-session produced *no*
94/// disconnect and *no* reconnect -- the session sat
95/// in its 500ms read deadline indefinitely, treating "nothing arrived" as a
96/// quiet game, which for a text MUD it usually is.
97///
98/// Keepalive is what makes that case distinguishable. The kernel sends empty
99/// ACK probes on an idle connection; when enough go unanswered it fails the
100/// socket, `read` returns an error, and [`EndReason::ReadFailed`] flows into
101/// the reconnect ladder that already exists. **No new policy, no new timer,
102/// and nothing sent to the game.**
103///
104/// # Why not an application-level ping
105///
106/// Because a command is the wrong layer. It would spend one of the account's
107/// type-ahead slots (MEASURED at 2), appear in the log indistinguishably from
108/// a real command, and risk roundtime -- while detecting nothing a kernel
109/// probe does not.
110///
111/// # Best-effort, and it SAYS SO when it fails
112///
113/// A failure does not stop the session -- one that works without keepalive is
114/// better than no session -- but it is **reported**, because the cost of the
115/// option not applying is that airplane-mode-style disappearance goes back to
116/// being undetectable, and that is the one thing this function exists to
117/// prevent.
118///
119/// `eprintln!` rather than the session log because this runs before a sink
120/// exists, and a silent degradation is the failure being guarded against.
121fn set_keepalive(stream: &TcpStream) {
122    let params = socket2::TcpKeepalive::new()
123        .with_time(KEEPALIVE_IDLE)
124        .with_interval(KEEPALIVE_INTERVAL);
125    // A borrowed view of the same socket -- it does not take ownership and
126    // does not close the fd when dropped.
127    if let Err(e) = socket2::SockRef::from(stream).set_tcp_keepalive(&params) {
128        eprintln!(
129            "[socket] WARNING: TCP keepalive could not be set ({e}). The \
130             session continues on OS defaults, but a connection that \
131             disappears without a FIN -- airplane mode, a dropped VPN -- may \
132             now hang instead of failing, which is what this setting exists \
133             to prevent."
134        );
135    }
136}

138/// Bound how long a SENT byte may go unacknowledged, where the platform lets
139/// this crate say so.
140///
141/// Best-effort and warned on failure, exactly as [`set_keepalive`] is and for
142/// the same reason: a session without it still works, but a write into a dead
143/// link goes back to hanging for the OS default, and nobody would know why.
144///
145/// # Only Linux and Android, and why not Windows
146///
147/// The equivalent exists on both families: `TCP_USER_TIMEOUT` on Unix and
148/// `TCP_MAXRT` on Windows. socket2 0.6.5 exposes the first and **not the
149/// second**, and setting it by hand is a raw `setsockopt`, which is `unsafe`,
150/// which the workspace denies (`Cargo.toml`, `unsafe_code = "deny"`). So
151/// Windows keeps its OS default. Changing that needs either an `unsafe`
152/// exception or a dependency that wraps the call.
153///
154/// macOS has `TCP_RXT_CONNDROPTIME`, which socket2 does not expose either.
155/// Nothing is claimed for it.
156///
157/// `SO_RCVTIMEO`/`SO_SNDTIMEO` are deliberately NOT set. Those bound a
158/// BLOCKING call; tokio's sockets are non-blocking, where the options do not
159/// apply. The read side is already bounded where it can be cancelled: the
160/// session's own read deadline.
161#[cfg(any(target_os = "linux", target_os = "android"))]
162fn set_user_timeout(stream: &TcpStream) {
163    if let Err(e) = socket2::SockRef::from(stream).set_tcp_user_timeout(Some(UNACKED_SEND_TIMEOUT))
164    {
165        eprintln!(
166            "[socket] WARNING: TCP_USER_TIMEOUT could not be set ({e}). The \
167             session continues, but a command written into a dead link may \
168             now wait out the kernel's ~15 minute retransmission default \
169             before the session notices."
170        );
171    }
172}

174/// No `TCP_USER_TIMEOUT` here -- see the Linux version's docs for why.
175#[cfg(not(any(target_os = "linux", target_os = "android")))]
176fn set_user_timeout(_stream: &TcpStream) {}

178/// Every option a GAME socket carries, in one place.
179///
180/// Shared by [`LiveSource::connect`] and [`LiveSource::connect_shim`] so the
181/// two routes to the same stream cannot drift. The eaccess socket
182/// takes only `nodelay` -- see [`LiveSource::connect_tls`] for why.
183fn configure_game_socket(stream: &TcpStream) -> io::Result<()> {
184    // Nagle batches small writes, which is exactly wrong for a stream of
185    // one-line commands: it would add up to 200ms to every round trip and
186    // make the PREEMPT_GRACE measurement a measurement of Nagle.
187    stream.set_nodelay(true)?;
188    set_keepalive(stream);
189    set_user_timeout(stream);
190    Ok(())
191}

193impl LiveSource {
194    /// Open a plain TCP connection.
195    ///
196    /// `tests/keepalive.rs` calls this against a LOOPBACK listener and reads
197    /// the options back off the socket it returns -- the only way to know
198    /// they are set by the code that runs, rather than by a test's own copy.
199    ///
200    /// # Errors
201    ///
202    /// The underlying connect error, unchanged: a caller that cannot reach the
203    /// host needs to know why, and wrapping it in a crate error type would be
204    /// an abstraction with one caller.
205    pub async fn connect(host: &str, port: u16) -> io::Result<Self> {
206        let stream = connect_bounded(host, port).await?;
207        configure_game_socket(&stream)?;
208        Ok(Self::Plain(stream))
209    }
210
211    /// Open the game stream through the WebSocket shim, for the game host and
212    /// port the login named.
213    ///
214    /// The socket goes to `shim_host`'s remap of `gamehost` on 443 and the game port
215    /// rides in the upgrade path. Nagle, keepalive and the send timeout are
216    /// set on the TCP socket underneath, for the same reasons as
217    /// [`Self::connect`]: they are socket options, and the WebSocket above
218    /// cannot set them.
219    ///
220    /// # Errors
221    ///
222    /// The TCP connect, TLS or upgrade failure.
223    pub async fn connect_shim(gamehost: &str, gameport: u16) -> io::Result<Self> {
224        let host = shim::shim_host(gamehost);
225        let stream = connect_bounded(host, shim::SHIM_PORT).await?;
226        configure_game_socket(&stream)?;
227        let shim = shim::ShimStream::open(stream, host, gameport).await?;
228        Ok(Self::WebSocket(Box::new(shim)))
229    }
230
231    /// Open a TLS connection for the eaccess handshake.
232    ///
233    /// # Three deliberate weakenings, and why each is required
234    ///
235    /// This connector is **not** `TlsConnector::new()`, which cannot work
236    /// against this server.
237    ///
238    /// 1. **`use_sni(false)`** -- the `ClientHello` carries no `server_name`
239    ///    extension. eaccess.play.net sits behind an AWS load balancer that
240    ///    may route on it, and the handshake is known to work without it, so
241    ///    this does not find out the hard way.
242    /// 2. **`danger_accept_invalid_certs(true)`** -- the server's certificate
243    ///    is **self-signed with no chain of trust**, so ordinary verification
244    ///    cannot succeed against it. The certificate is pinned instead.
245    /// 3. **`danger_accept_invalid_hostnames(true)`** -- follows from 1 and 2.
246    ///    With no SNI and no chain, there is no name to check against.
247    ///
248    /// # What replaces the verification: the pin
249    ///
250    /// **This function does not verify the peer, and must not be the last
251    /// thing between the network and the password.** Its one caller is
252    /// `eaccess::pin::open_pinned`, which reads the certificate off the
253    /// finished handshake ([`Self::peer_certificate_der`]) and compares it
254    /// with the pin in `simu.pem` before the conversation sends a byte:
255    /// trust on first use, and a **fatal** refusal on change. A pin that
256    /// re-pinned silently on a mismatch would let an attacker who intercepts
257    /// one connection install a persistent pin. Read `eaccess/pin.rs` for the
258    /// whole argument.
259    ///
260    /// `pub(crate)`, not `pub`, for exactly that reason: outside this crate
261    /// there is no way to open the eaccess TLS connection except through the
262    /// pin.
263    ///
264    /// What the pin cannot do is vouch for the FIRST connection. A machine
265    /// with no `simu.pem` trusts whatever it reaches first. The first-use line
266    /// in the login output says so.
267    ///
268    /// # Errors
269    ///
270    /// Connect, TLS-builder and handshake errors, each mapped to
271    /// [`io::Error`] so one `?` chain covers the sequence.
272    pub(crate) async fn connect_tls(host: &str, port: u16) -> io::Result<Self> {
273        let stream = connect_bounded(host, port).await?;
274        stream.set_nodelay(true)?;
275        // NO keepalive here, unlike the game socket. This connection is a
276        // handshake -- a few request/response pairs that finish in seconds,
277        // each already bounded by `eaccess`'s per-stage deadline. Keepalive
278        // guards a connection that sits IDLE for minutes, which this one never
279        // does. Stated because its absence beside `connect`'s presence would
280        // otherwise read as an oversight.
281        let connector = native_tls::TlsConnector::builder()
282            .danger_accept_invalid_certs(true)
283            .danger_accept_invalid_hostnames(true)
284            .use_sni(false)
285            .build()
286            .map_err(|e| io::Error::other(format!("tls connector: {e}")))?;
287        let connector = tokio_native_tls::TlsConnector::from(connector);
288        // The TLS handshake is bounded too: CONNECT_TIMEOUT covers only the
289        // TCP handshake, and an unbounded TLS handshake can hang forever.
290        let tls = tokio::time::timeout(TLS_HANDSHAKE_TIMEOUT, connector.connect(host, stream))
291            .await
292            .map_err(|_elapsed| {
293                io::Error::new(
294                    io::ErrorKind::TimedOut,
295                    format!("tls handshake with {host} did not complete within {TLS_HANDSHAKE_TIMEOUT:?}"),
296                )
297            })?
298            .map_err(|e| io::Error::other(format!("tls handshake with {host}: {e}")))?;
299        Ok(Self::Tls(Box::new(tls)))
300    }
301
302    /// The certificate the peer presented in the TLS handshake, as DER.
303    ///
304    /// For the eaccess pin (`eaccess/pin.rs`), which is what stands in for
305    /// the chain verification [`Self::connect_tls`] turns off.
306    ///
307    /// # Errors
308    ///
309    /// Not a [`Self::Tls`] connection, no certificate presented, or the TLS
310    /// library could not encode it.
311    pub(crate) fn peer_certificate_der(&self) -> io::Result<Vec<u8>> {
312        let Self::Tls(tls) = self else {
313            return Err(io::Error::other("not a TLS connection"));
314        };
315        tls.get_ref()
316            .peer_certificate()
317            .map_err(io::Error::other)?
318            .ok_or_else(|| io::Error::other("the server presented no certificate"))?
319            .to_der()
320            .map_err(io::Error::other)
321    }
322}

324/// Bound on the TCP handshake.
325///
326/// 5 seconds. A **silently-dropped SYN** -- firewalled or blocked, with no RST
327/// -- otherwise hangs on the OS connect timeout, commonly ~75s on Linux. That
328/// has been seen against the login host.
329const CONNECT_TIMEOUT: std::time::Duration = std::time::Duration::from_secs(5);
330
331/// Bound on the TLS handshake, which `CONNECT_TIMEOUT` does not cover.
332const TLS_HANDSHAKE_TIMEOUT: std::time::Duration = std::time::Duration::from_secs(10);
333
334/// `TcpStream::connect`, bounded by [`CONNECT_TIMEOUT`].
335///
336/// Shared by both constructors: an unreachable game host hangs exactly as an
337/// unreachable login host does, and there is no reason for one to be bounded
338/// and the other not.
339async fn connect_bounded(host: &str, port: u16) -> io::Result<TcpStream> {
340    tokio::time::timeout(CONNECT_TIMEOUT, TcpStream::connect((host, port)))
341        .await
342        .map_err(|_elapsed| {
343            io::Error::new(
344                io::ErrorKind::TimedOut,
345                format!(
346                    "no TCP connection to {host}:{port} within {CONNECT_TIMEOUT:?}. A \
347                     dropped SYN with no RST otherwise hangs on the OS timeout \
348                     (~75s on Linux, ~21s on Windows)."
349                ),
350            )
351        })?
352}

354impl ByteSource for LiveSource {
355    async fn read(&mut self, buf: &mut [u8]) -> io::Result<usize> {
356        match self {
357            Self::Plain(s) => s.read(buf).await,
358            Self::Tls(s) => s.read(buf).await,
359            Self::WebSocket(s) => s.read(buf).await,
360        }
361    }
362
363    async fn write_all(&mut self, message: &[u8]) -> io::Result<()> {
364        // ONE write of the finished message, then flush. See fact 1 in this
365        // module's docs: splitting this into a write of the body and a write
366        // of the newline emits two TLS records and the server drops the
367        // command.
368        match self {
369            Self::Plain(s) => {
370                s.write_all(message).await?;
371                s.flush().await
372            }
373            Self::Tls(s) => {
374                s.write_all(message).await?;
375                s.flush().await
376            }
377            // One message is one WebSocket frame, which is one TLS write.
378            Self::WebSocket(s) => s.write_all(message).await,
379        }
380    }
381
382    async fn shutdown(&mut self) -> io::Result<()> {
383        let result = match self {
384            Self::Plain(s) => s.shutdown().await,
385            Self::Tls(s) => s.shutdown().await,
386            Self::WebSocket(s) => s.shutdown().await,
387        };
388        // Idempotence (the trait's contract): a second
389        // shutdown on a closed socket returns NotConnected on every platform
390        // this targets, and that is success, not failure. The session shuts
391        // down on three paths -- cancel, end of stream, read error -- and they
392        // are not mutually exclusive.
393        match result {
394            Err(e) if e.kind() == io::ErrorKind::NotConnected => Ok(()),
395            other => other,
396        }
397    }
