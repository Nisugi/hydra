1//! A character's log window: the player log read back.
2//!
3//! One window per character, its own viewport as the settings menu is,
4//! opened from the play window's top bar and the hub card. Three tabs:
5//! *Recent* (a day, whole), *Search* and *Export*, over
6//! `hydra_session::player_log`'s reader, archive and export.
7//!
8//! # Reading is off the window's thread
9//!
10//! Every read runs on a blocking task of the runtime, its
11//! answer landing in the window's inbox and waking it. The writer flushes
12//! every second, so a read sees all but the last second of a live session.
13//! This file holds what the window shows and what it asks, and runs a read
14//! ([`run`]) where it is told to; `draw.rs` draws it.
15//!
16//! # Filters, presets and *Dedup* are a reading view
17//!
18//! A line is shown when its **class** is ticked: the last part of its tag,
19//! so `main/combat` is `combat` and `main` is `main` (the class is what
20//! Hydra's definitions made of the line). The presets tick a set of
21//! classes, and *Dedup* folds a run of the same line into one with its
22//! count. None of it changes what is read or counted: an export writes
23//! every line of the ticked classes.
24

36/// `mutex`'s value, even when a thread that held it panicked: a read is
37/// only lines.
38pub(crate) fn lock<T>(mutex: &std::sync::Mutex<T>) -> std::sync::MutexGuard<'_, T> {
39    mutex
40        .lock()
41        .unwrap_or_else(std::sync::PoisonError::into_inner)
42}
