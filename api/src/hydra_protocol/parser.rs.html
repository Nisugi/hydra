1//! The line transducer: bytes in, [`Frame`]s out.
2//!
3//! # Why hand-rolled and not an XML library
4//!
5//! The wire has **no root element**. It is an unbounded sequence of fragments,
6//! and several tags are mode switches with no close: a corpus sample of
7//! 5,079,826 tags measured 23,328 `<style ...>` opens and **zero** `</style>`
8//! closes, plus `<output class="mono"/>` / `<output class=""/>` as an
9//! open/close pair that is self-closing at both ends. A tree-building parser
10//! must either error or invent structure, and this parser never errors on
11//! unknown input.
12//!
13//! The malformations that would justify a tolerant library are **absent**. In
14//! that same sample: 0 tags split across a newline, 0 unquoted attribute
15//! values, 0 tags opened without a `>` on the line. The wire is well-lexed
16//! even though it is not well-formed. A substring scanner is sufficient, and
17//! sufficient is the simplest answer.
18//!
19//! # The read boundary
20//!
21//! **A [`Parser`] consumes whole lines and never sees a TCP fragment.** The
22//! socket reassembles with `read_until(b'\n')` before decoding, which is
23//! correct: the measurement above says the line is a safe frame boundary on
24//! this wire. `read_until` on bytes rather than `read_line` on a `String` is
25//! also load bearing -- the stream is CP1252, and `read_line` returns
26//! `InvalidData` on any non-UTF-8 byte, which would hard-disconnect a client.
27//!
28//! [`Parser::push_bytes`] implements that reassembly here, so the rule is
29//! enforced by this crate rather than assumed of its caller, and so a test can
30//! drive a split at every byte offset.
31//!
32//! **A tag with no `>` before the line ends is not prose.** Appended to the
33//! text buffer, it would silently desync parser state. Here it is
34//! [`Frame::MalformedTag`]: typed, logged, rendered.
35//!
36//! # MULTI-LINE CAPTURES: measured, and deliberately not built
37//!
38//! Buffering a `<compDef>`/`<component>`/`<inv>` whose close tag is on a later
39//! line, accumulating until the close arrives, is **not built**, on evidence:
40//!
41//! ```text
42//! $ grep -h -cE '<(compDef|component|inv)[^>]*>[^<]*$' <272 stratified files>
43//! 0                       # opens with no close on the same line
44//! $ grep -h -o '<compDef' <same files> | wc -l
45//! 447095                  # opens in total
46//! ```
47//!
48//! and, driving the parser over 60 of those files, **1,230,355 wire lines
49//! with no such open.** Two years of traffic does not contain the case.
50//!
51//! Such a buffer would also be a black hole. Bounded by `MAX_LINE_BYTES` of
52//! *accumulated body*, which is not a bound on frames lost, at a realistic
53//! 60-character line it would swallow **4,297 consecutive lines of game
54//! text** before the cap fired -- 3,236 at 80 characters, 1,019 at 256. Only
55//! a `<prompt>` would break it sooner. That is a multi-thousand-line
56//! silent-loss risk for a case the wire has never produced.
57//!
58//! An unclosed paired tag is [`Frame::MalformedTag`], same as any other
59//! tag with no terminator: typed, surfaced, and bounded to its own line.
60//! **Upgrade trigger:** if the corpus replay ever reports a `MalformedTag`
61//! whose `raw` begins `<compDef`, `<component` or `<inv`, the wire has started
62//! sending this and a buffering path is needed -- bounded by *lines*, two
63//! or three, not by bytes.
64//!
65//! # The prompt as a resync barrier
66//!
67//! At every `<prompt>`, force-close open streams and drop orphaned markup.
68//! It is what makes the push/pop imbalance harmless -- the
69//! corpus has 19,142 `pushStream` against 14,714 `popStream`, because
70//! `pushStream` is not a stack discipline. Prompts are frequent (207,626 in
71//! the sample), so this **bounds all state corruption to one round**.
72//!
73//! # What this parser does NOT do
74//!
75//! It does not drop lines that look like GSL framing by their first letters.
76//! A rule that drops any line beginning `GS` + a lowercase letter also
77//! swallows `"GSrule violations are handled by the GameMasters."` and
78//! `"GShaldi the merchant nods at you."` -- ordinary game prose, silently
79//! discarded. Hydra talks to the game directly, so the case is live. GSL
80//! framing, when needed, must key on the `\x1C` prefix that actually marks it.

98/// Hard ceiling on a single accumulated line.
99///
100/// A close tag that never comes must not buffer forever. At the limit the
101/// buffer is flushed as text rather than grown, so a hostile or
102/// broken peer costs bounded memory instead of the process.
103const MAX_LINE_BYTES: usize = 256 * 1024;
104
105/// Stateful, per-session line transducer.
106///
107/// One per session: it holds the stream stack and markup state for **that**
108/// character's connection. It is an owned value with no `static` behind it --
109/// no process globals -- which is what lets many sessions share a process.
110#[derive(Debug, Default)]
111pub struct Parser {
112    /// Bytes received but not yet terminated by a newline.
113    pending: Vec<u8>,
114    /// Streams opened and not yet closed; the last is current.
115    streams: Vec<OpenStream>,
116    /// Open `<pushBold>` scopes.
117    bold_depth: u16,
118    /// Innermost `<preset>` / `<style>` id, if any.
119    presets: Vec<String>,
120    /// Inside an `<output class="mono"/>` region.
121    mono: bool,
122    /// Open `<a>` / `<d>` links, outermost first.
123    links: Vec<crate::frame::Link>,
124    /// Links opened past the depth that is kept, and not yet closed.
125    links_over: u32,
126    /// The `<dialogData id=>` currently open, if any.
127    ///
128    /// Vitals arrive as `<progressBar>` *inside* `<dialogData id='minivitals'>`,
129    /// and the same bar id appears in other dialogs -- `health` in
130    /// `minivitals` and `health2` in `injuries`. Without the enclosing id a
131    /// consumer cannot tell which gauge it is looking at.
132    dialog: Option<String>,
133    /// Where the parser stands relative to the login `<settings>` blob.
134    ///
135    /// State rather than a within-line scan because the blob exceeds a line:
136    /// 513,700 bytes in one measured case, which `MAX_LINE_BYTES` splits.
137    settings: wire::SettingsRegion,
138    /// The last few bytes seen inside a `<settings>` blob, for matching its
139    /// close across a read boundary.
140    ///
141    /// At most `SETTINGS_CLOSE.len()` bytes, so a 786 KB blob costs eleven bytes
142    /// of state rather than 786 KB of buffer. That is what lets `push_bytes`
143    /// skip the line cap entirely while a blob is open -- see its settings
144    /// arm for why.
145    settings_tail: Vec<u8>,
146    /// The `<inventoryViewItem>` block being captured across lines.
147    ///
148    /// The parser's ONLY multi-line capture. See `view_item.rs` for why this
149    /// one exists when there is no general capture path, and for the line
150    /// bound that keeps its worst case countable.
151    view_item: Option<view_item::ViewItem>,
152    /// Discarding the tail of a line that exceeded [`MAX_LINE_BYTES`].
153    ///
154    /// Set when the cap fires, cleared by the next newline. It is what lets
155    /// the parser resume on a known boundary instead of mid-token: see
156    /// [`Parser::push_bytes`] for the markup-into-prose failure it prevents.
157    dropping_oversized_line: bool,
158}

160/// One open stream redirect, and **which tag opened it**.
161///
162/// The opener matters because the two forms have different closers, and only
163/// the paired one is reliably balanced. MEASURED over 24 corpus files across
164/// three years: `<stream id=>`/`</stream>` came to **122 opens and 122 closes,
165/// with no file where they differed**, while `<pushStream>`/`<popStream>` came
166/// to 17,036 against 13,039 -- the 1.301 imbalance the prompt barrier exists
167/// to absorb.
168///
169/// So `</stream>` must close a stream a paired `<stream>` opened, and never an
170/// enclosing `<pushStream>` redirect. Without the opener recorded there is no
171/// way to honour that: with a stack of bare ids, a closer guessing
172/// "innermost non-empty id" would let a paired `<stream>` nested inside a
173/// `<pushStream id='inv'/>` pop `inv`.
174#[derive(Clone, Debug, PartialEq, Eq)]
175struct OpenStream {
176    /// The `id=` attribute; `""` for a `<pushStream>` with no id.
177    id: String,
178    /// Whether the opener was the paired `<stream id=>` form.
179    paired: bool,
180}

182impl Parser {
183    /// A parser with no state. Cheap; one per session.
184    #[must_use]
185    pub fn new() -> Self {
186        Self::default()
187    }

189    /// Parse one complete line, newline already removed.
190    ///
191    /// Never panics on any input: `tests/parser_never_panics.rs` drives it
192    /// with arbitrary bytes and with real malformed corpus fragments.
193    pub fn parse_line(&mut self, line: &str) -> Vec<Frame> {
194        // **Wrapped so the line-end mark happens exactly once, on every path.**
195        // The inner function has several early returns -- a settings blob, a
196        // blank line, the oversized guard -- and marking at each is the version
197        // that rots: a new early return would silently emit text runs that no
198        // consumer could terminate, which is what `ends_line` exists to prevent.
199        let mut frames = self.parse_line_inner(line);
200        Self::mark_line_end(&mut frames);
201        // **Link state does not cross a line boundary.**
202        //
203        // `links` is popped by `</a>`/`</d>`; cleared only by a prompt, an
204        // unclosed `<a href='x'>` would keep accumulating: every later `Text`
205        // frame would carry the whole prefix, and clone it. Over three
206        // prompt-less lines:
207        //
208        // ```text
209        // link.text = "unclosed linksecond line here"
210        // link.text = "unclosed linksecond line herethird line here"
211        // ```
212        //
213        // That is O(N^2) bytes through the broadcast ring for N lines, on
214        // input this crate's own hostile-fragment tests produce.
215        //
216        // Clearing here rather than tracking the close is right because this
217        // parser is LINE-SCOPED by design: a paired tag whose close is not on
218        // the same line becomes a `MalformedTag` rather than being buffered
219        // (see `parse_line_inner`'s close-tag scan, and MULTI-LINE CAPTURES in
220        // the module header). Link state surviving the boundary would
221        // contradict that, and the corpus has no tag spanning a line.
222        self.links.clear();
223        self.links_over = 0;
224        frames
225    }
226
227    fn parse_line_inner(&mut self, line: &str) -> Vec<Frame> {
228        let line = line.trim_end_matches(['\r', '\n']);
229        let mut frames = Vec::new();
230
231        let Some(mut rest) = self.continue_settings_blob(line) else {
232            return frames;
233        };
234
235        // An open `<inventoryViewItem>` owns the line until its close.
236        if self.view_item.is_some() {
237            self.begin_captured_line(&mut frames);
238        }
239        if self.view_item.is_none() && rest.is_empty() {
240            // Preserve intentional blank lines: vertical spacing is content.
241            frames.push(self.text_frame(""));
242            return frames;
243        }
244
245        // **One loop, two modes, and no recursion.** A line can open and
246        // close captures any number of times. Were each handoff a nested
247        // call -- `parse_line` into the capture and back into `parse_line` --
248        // 2,000 `<inventoryViewItem>` open/close pairs on one 92 KB line,
249        // under the line cap, would overflow a 2 MiB stack in a release
250        // build. That is an abort, not a panic, so it would take every
251        // session in the process with it.
252        //
253        // Each turn either consumes at least one tag or switches mode, so this
254        // terminates, and stack depth no longer depends on the input.
255        loop {
256            let next = if self.view_item.is_some() {
257                self.view_item_line(rest, &mut frames)
258            } else {
259                self.parse_ordinary(rest, &mut frames)
260            };
261            match next {
262                Some(after) => rest = after,
263                None => return frames,
264            }
265        }
266    }
267
268    /// Parse `line` outside any capture, until it ends or opens one.
269    ///
270    /// Returns the rest of the line when an `<inventoryViewItem>` opened
271    /// part-way through it, for the capture to take over.
272    fn parse_ordinary<'a>(&mut self, line: &'a str, frames: &mut Vec<Frame>) -> Option<&'a str> {
273        let mut buffer = String::new();
274        let mut rest = line;
275
276        while !rest.is_empty() {
277            let Some(start) = text::find_tag_start(rest) else {
278                buffer.push_str(rest);
279                break;
280            };
281            if start > 0 {
282                buffer.push_str(&rest[..start]);
283            }
284            let tail = &rest[start..];
285
286            // `<!-- CLIENT --> ... <!-- ENDCLIENT -->` is a client-echo
287            // REGION, not a comment pair, and everything inside it is the
288            // client's own traffic rather than server output: `!--`,
289            // `stgupd`, `options`, `o`, `w` and `<r` appear inside such a
290            // region, none of them ever sent by the game.
291            //
292            // The player's typed command is the one part worth keeping:
293            // `<!-- CLIENT --><c>;go2 3609<!-- ENDCLIENT -->` is how a replay
294            // knows what the player did. So the region is consumed here and
295            // its `<c>` body becomes a frame; the settings chatter around it
296            // is discarded with the region rather than misread as protocol.
297            if tail.starts_with(CLIENT_OPEN) {
298                self.flush(&mut buffer, frames);
299                let (frame, after) = client_region(tail);
300                if let Some(frame) = frame {
301                    frames.push(frame);
302                }
303                rest = after;
304                continue;
305            }
306
307            // `<settings> ... </settings>` is the client-configuration blob
308            // the server sends once at login: window layout, palettes,
309            // highlight strings, sound files, macros. It is a self-contained
310            // document with its own vocabulary -- `h`, `dc`, `cmdline`,
311            // `ignores`, `panels`, `toggles` and about twenty more, none of
312            // them game protocol.
313            //
314            // The open tag, the close tag and all the inner names arrive as
315            // one blob. The right unit is the REGION, not a list of names to
316            // keep extending.
317            //
318            // Hydra keeps its own configuration, so the blob is consumed
319            // whole and reported as one frame. Modelling its contents would
320            // claim a protocol understanding this crate does not have;
321            // letting its inner names reach `UnknownTag` would cry wolf on
322            // every login.
323            // The region is parser STATE, not a within-line scan, because the
324            // blob can be bigger than a line -- over 500 KB on one line, which
325            // the MAX_LINE_BYTES guard necessarily splits. A scan that only
326            // looked inside this line would lose the close and leak the blob's
327            // private element names into UnknownTag on every login.
328            if tail.starts_with("<settings ") || tail.starts_with("<settings>") {
329                self.flush(&mut buffer, frames);
330                frames.push(Frame::ClientSettings);
331                let Some(at) = tail.find(SETTINGS_CLOSE) else {
332                    self.settings = wire::SettingsRegion::Open;
333                    break;
334                };
335                rest = &tail[at + SETTINGS_CLOSE.len()..];
336                continue;
337            }
338
339            // Any other XML comment is not an element: it has no name, and `>`
340            // may appear inside it, so it is consumed on its own terms.
341            if let Some(body) = tail.strip_prefix("<!--") {
342                let Some(at) = body.find(COMMENT_CLOSE) else {
343                    self.flush(&mut buffer, frames);
344                    frames.push(Frame::MalformedTag {
345                        raw: tail.to_owned(),
346                    });
347                    break;
348                };
349                rest = &body[at + COMMENT_CLOSE.len()..];
350                continue;
351            }
352
353            // The first `>` ends the tag, quoted or not. A `>` inside a quoted
354            // attribute value would cut the tag short here; the game writes
355            // one as `&gt;`. Over 1,371 recorded session files chosen at
356            // random there is no tag with a raw `>` inside a quoted value
357            // (the regex
358            // `<[A-Za-z][^<>]*?(?:"[^"<]*>[^"<]*"|'[^'<]*>[^'<]*')[^<]*?>`
359            // over each file's bytes). Left as it is on that evidence; the
360            // trigger to change it is one such tag on the wire.
361            let Some(close) = tail.find('>') else {
362                // A tag that never closed is typed and logged, not smuggled
363                // into prose, where it would silently desync the parser.
364                self.flush(&mut buffer, frames);
365                frames.push(Frame::MalformedTag {
366                    raw: tail.to_owned(),
367                });
368                break;
369            };
370            let open = &tail[..=close];
371            rest = &tail[close + 1..];
372
373            // A paired tag is handed to dispatch WHOLE -- `<prompt>x</prompt>`,
374            // not `<prompt>` -- because its body is the frame's content. Cut
375            // at the first `>` instead and every paired handler sees an empty
376            // body.
377            let mut tag = open;
378            if !open.ends_with("/>") && !text::is_close_tag(open) && is_paired(open) {
379                let close_tag = format!("</{}>", text::tag_name(open));
380                // A paired tag whose close is not on this line is typed and
381                // surfaced, never buffered: see MULTI-LINE CAPTURES in the
382                // module header for the measurement behind that. The answer
383                // is a frame rather than a silent drop, as for any tag that
384                // cannot be read.
385                let Some(at) = tail.find(&close_tag) else {
386                    self.flush(&mut buffer, frames);
387                    frames.push(Frame::MalformedTag {
388                        raw: tail.to_owned(),
389                    });
390                    break;
391                };
392                let end = at + close_tag.len();
393                tag = &tail[..end];
394                rest = &tail[end..];
395            }
396
397            self.dispatch(tag, &mut buffer, frames);
398
399            // Opening an `<inventoryViewItem>` hands the REST of this line to
400            // the capture. Without this the envelope would open the capture
401            // and the line keep parsing normally, so the
402            // `<result command='look'>` that follows it on the same line
403            // would route to `WindowHints` and its whole section be lost --
404            // one section per response.
405            if self.view_item.is_some() && !rest.is_empty() {
406                self.flush(&mut buffer, frames);
407                return Some(rest);
408            }
409        }
410
411        self.flush(&mut buffer, frames);
412        None
413    }
414}

416/// Tags whose body is content and must be dispatched whole.
417///
418/// `<a>` and `<d>` are absent deliberately: their bodies are display text that belongs
419/// in the text stream, so they stay markup tags and their close is what pops
420/// the link.
421///
422/// Three of these -- `menu`, `objectives`, `inventoryManager` -- have bodies
423/// of CHILDREN rather than text, and are here because something assembles
424/// those children (`dispatch.rs`). Left out, the children would tokenize
425/// separately and land in `WindowHints`.
426fn is_paired(tag: &str) -> bool {
427    matches!(
428        text::tag_name(tag),
429        "prompt"
430            | "compass"
431            | "spell"
432            | "left"
433            | "right"
434            | "component"
435            | "compDef"
436            | "inv"
437            | "worldEvent"
438            // A context menu's body is a run of `<mi>` children, so it is
439            // captured whole and assembled in `dispatch.rs`. Without this the
440            // items tokenize separately and arrive orphaned from the menu
441            // that answers for them.
442            //
443            | "menu"
444            | "objectives"
445            // A whole-inventory snapshot: one line, ~150 items, all of them
446            // `<i>` children. Without this each row would tokenize on its
447            // own and the snapshot never be assembled.
448            | "inventoryManager"
449            // The server teaching us dictionary rows. Without this each
450            // `<cli>` tokenizes separately into `WindowHints` -- carrying its
451            // attributes, so nothing is lost, but arriving with nothing to
452            // join them to.
453            | "cmdlist"
454    )
