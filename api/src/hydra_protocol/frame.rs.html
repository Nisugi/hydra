1//! The frame vocabulary: what the wire can say.
2//!
3//! A [`Frame`] is one thing the game said, typed. The list of variants is
4//! the protocol's vocabulary as Hydra understands it; [`crate::tags`] lists
5//! the tag names behind it.
6//!
7//! # What is deliberately not a frame
8//!
9//! - **Client-side inventions.** Tags a client injects into its own log, and
10//!   events a client raises from user-configured patterns over text, are not
11//!   wire vocabulary. A protocol parser whose output depends on a user's
12//!   config file is not a protocol parser; game meaning belongs above this
13//!   layer, consuming frames. A client tag that does reach the wire falls to
14//!   [`Frame::UnknownTag`].
15//! - **One variant per widget.** The dialog widget tags (buttons, controls,
16//!   drop-downs, fields, label lists, progress bars) are one shape -- "the
17//!   game sent a widget tag with these attributes" -- so they are one
18//!   [`payload::DialogWidgets`] keyed by the tag name. [`Frame::DialogOpen`]
19//!   and [`Frame::DialogPanelOpen`] are separate; they carry a dialog, not a
20//!   widget.
21//! - **A variant nothing constructs.** Every variant here is produced by the
22//!   parser. Dialogs not yet modelled (injuries as a popup, the quickbar's
23//!   entries, the target drop-down) come back with their handlers, in one
24//!   change, when they are needed.
25//!
26//! [`Frame::UnknownTag`], [`Frame::MalformedTag`] and [`Frame::Structural`]
27//! are Hydra's own: the first two so a protocol change or a broken tag is
28//! visible rather than dropped or mistaken for prose, the third so the tags
29//! that carry no payload of their own are seen too. [`Frame::ClientCommand`]
30//! and [`Frame::ClientSettings`] type the regions a log carries around the
31//! player's own commands and the login's settings blob, and
32//! [`Frame::CmdListUpdate`] and [`Frame::CmdTimestamp`] the dictionary rows
33//! that keep the game's command labels current.
34//!
35//! # Presentation is not here
36//!
37//! The `Frame` is the vocabulary boundary; this crate carries wire shape,
38//! not render intent:
39//!
40//! - There is no render class (normal, link, monsterbold, spell, speech).
41//!   The preset id travels as data in [`Style::preset`] instead, so a preset
42//!   the game invents tomorrow needs no change in this crate.
43//! - Colours are not resolved here. A palette is user configuration, and
44//!   resolving it would make the same bytes give different frames under a
45//!   different theme, which is disqualifying for a replay test. This crate
46//!   emits the markup structure and the layer that draws resolves colour.
47//! - A link's kind is a real enum, [`LinkKind`], not a marker stuffed into a
48//!   string. Which URL schemes may be opened is click-safety policy and
49//!   belongs with the layer that opens browsers.
