1//! `<crtrStatus>`: what the wire says a creature is doing right now.
2//!
3//! A stateless classifier over one frame, reading two flag tables.
4//!
5//! # Two vocabularies, because they answer different questions
6//!
7//! They are kept apart and read through different predicates, because the
8//! distinction is real:
9//!
10//! - **[`Status`]** is transient -- `stunned`, `webbed`, `prone`. It changes
11//!   several times per fight and is the answer to *what is it doing*.
12//! - **[`Classification`]** is a standing fact -- `hostile`, `dead`,
13//!   `MiniBoss`. It is the answer to *what is it*.
14//!
15//! A caller picking a target wants both and wants them apart: a `stunned`
16//! creature is worth attacking, a `dead` one is not, and no single flag set
17//! makes that distinction legible.
18//!
19//! # One flag is renamed on the way in
20//!
21//! The wire says `immobile` and the canonical name is `immobilized`, because
22//! the combat messages use the longer word and the two detections have to
23//! reconcile. The wire spelling is what [`Status::parse`] accepts and the
24//! canonical spelling is what [`Status::as_str`] prints, so both ends stay
25//! readable.
26//!
27//! MEASURED in `crates/hydra-protocol/tests/fixtures/creature_status.xml`:
28//! `immobile` appears on the wire, `immobilized` never does.
29//!
30//! # The frame hands up raw attributes deliberately
31//!
32//! `Frame::CreatureStatus` keeps `attrs` unparsed *"so the layer above owns
33//! the flag-name mapping"* (`frame.rs`). This is that layer.
34//!
35//! # Real hit points, and when they started arriving
36//!
37//! `health=` and `maxhealth=` are **absolute hit points**, not a percentage
38//! and not a flag: `health="30" maxhealth="600"` is a creature nearly dead.
39//! This is the game's own answer to a question that used to require
40//! inference -- a combat tracker accumulating damage against a bestiary
41//! estimate, which is what [`CreatureInstance`](crate::CreatureInstance)
42//! still does when the wire says nothing.
43//!
44//! **The feature is recent.** MEASURED over a month of logs: health appears
45//! in **2 files of 127**, both from the most recent days, and in **zero**
46//! older ones -- including one session carrying 11,414 `<crtrStatus>` tags
47//! and no health at all. The same creature proves it is not a per-creature
48//! property: the jeweler Etaenia (`exist="-285052"`) appears **236 times
49//! without health and 7 times with**.
50//!
51//! An attribute nobody has typed yet lands in [`CreatureStatus::unknown`]
52//! rather than being dropped, which is how a protocol change like this one
53//! surfaces.
54//!
55//! ## Hostile creatures always carry it
56//!
57//! The server is taken to send hit points for every hostile creature.
58//! VERIFIED in the two health-era files: **331 of 331** rows carrying
59//! `hostile=` also carry `health=`, with none missing it.
60//!
61//! ## Health goes NEGATIVE, so it is signed
62//!
63//! A dead creature reads `health="-10" maxhealth="360" dead="1"`. An unsigned
64//! field cannot parse that: it fails, and [`CreatureStatus::health`] silently
65//! becomes `None` -- so a creature with a `dead` flag would report *no health
66//! information at all*, which is the opposite of what the row says.
67//!
68//! MEASURED on a real log: read unsigned, 327 of 331 hostile rows carry
69//! health where raw `grep` counts 331. The four lost are the dead ones.
70//!
71//! ## `maxhealth="0"` means no HP model, NOT "not hostile"
72//!
73//! All 42 `maxhealth="0"` rows are non-hostile, so reading a zero as a
74//! non-combatant holds in that direction. It does **not**
75//! invert: the jeweler carries `health="240" maxhealth="240"` and is not
76//! hostile. So a zero max is "this NPC has no hit points to speak of", and
77//! [`CreatureStatus::health_percent`] returns `None` for it rather than
78//! dividing by zero.
79//!
80//! # A flag that is present but `0` is OFF
81//!
82//! The wire writes `stunned="1"` to set and may write `stunned="0"` to clear.
83//! Both are a statement, which is why [`CreatureStatus::from_attrs`] records
84//! `false` rather than absence for the second -- and why
85//! [`CreatureStatus::stated`] exists: a caller can tell "the game said it is
86//! not stunned" from "the game did not mention stunned".

211    /// **Does this status stop the creature acting?**
212    ///
213    /// "Muckled". The one question a hunting consumer asks of a status set, and
214    /// the reason the vocabulary is
215    /// typed rather than a bag of strings.
216    ///
217    /// `Prone`, `Kneeling`, `Sitting`, `Flying`, `Hovering` and `Hidden` are

234/// A standing fact about a creature, rather than a transient state.

252    AscensionBoss,
253    /// A mini-boss.
254    MiniBoss,

309/// One creature's status, as a single `<crtrStatus>` stated it.
310///
311/// **This is what the frame said, not accumulated state.** A creature's status
312/// over time is a stateful consumer's job (the creature registry); this is
313/// the classifier under it.
314#[derive(Debug, Clone, Default, PartialEq, Eq)]
315pub struct CreatureStatus {
316    /// The `exist=` id this frame is about.
317    pub id: String,
318    /// Each transient status the frame mentioned, and whether it was set.
319    pub statuses: BTreeMap<Status, bool>,
320    /// Each classification the frame mentioned, and whether it was set.
321    pub classifications: BTreeMap<Classification, bool>,
322    /// `health=`: current hit points, absolute.
323    ///
324    /// **Signed**: a dead creature reads `health="-10"`. `None` when
325    /// unstated.
326    pub health: Option<i32>,
327    /// `maxhealth=`: maximum hit points. `None` when unstated, and `0` when
328    /// the creature has no HP model -- see [`Self::health_percent`].
329    pub max_health: Option<u32>,
330    /// Attributes that are neither, other than `exist`.
331    ///
332    /// Non-empty means the game added a flag since this table was cut. Kept
333    /// and counted rather than ignored -- a silently dropped flag
334    /// is how a client stops noticing that creatures can now be, say, `feared`.
335    pub unknown: BTreeMap<String, String>,
336}
337
338impl CreatureStatus {
339    /// Classify one `<crtrStatus>` frame's attributes.
340    ///
341    /// `id` is the frame's `exist=`; `attrs` its remaining attributes.
342    #[must_use]
343    pub fn from_attrs<'a, I>(id: &str, attrs: I) -> Self
344    where
345        I: IntoIterator<Item = (&'a str, &'a str)>,
346    {
347        let mut out = Self {
348            id: id.to_owned(),
349            ..Self::default()
350        };
351        for (name, value) in attrs {
352            if name == "exist" {
353                continue;
354            }
355            // Absolute hit points, not flags: parsed as numbers before the
356            // `"0"`-means-off rule below, which would read `health="0"` --
357            // a dead creature -- as "the health flag is off".
358            match name {
359                "health" => {
360                    out.health = value.trim().parse().ok();
361                    continue;
362                }
363                "maxhealth" => {
364                    out.max_health = value.trim().parse().ok();
365                    continue;
366                }
367                _ => {}
368            }
369            // `stunned="1"` sets, `stunned="0"` clears. Both are statements.
370            let on = value != "0";
371            if let Some(status) = Status::parse(name) {
372                out.statuses.insert(status, on);
373            } else if let Some(class) = Classification::parse(name) {
374                out.classifications.insert(class, on);
375            } else {
376                out.unknown.insert(name.to_owned(), value.to_owned());
377            }
378        }
379        out
380    }
381
382    /// Current health as a percentage, 0..=100.
383    ///
384    /// `None` when either value is unstated, **or when `maxhealth` is 0** --
385    /// an NPC with no HP model, 42 such rows in a month of logs. Reporting
386    /// 0% for a shopkeeper would read as "nearly dead" to anything choosing
387    /// a target.
388    #[must_use]
389    pub fn health_percent(&self) -> Option<u32> {
390        let (health, max) = (self.health?, self.max_health?);
391        if max == 0 {
392            return None;
393        }
394        // Negative health is a dead creature, and 0% is the honest reading;
395        // clamping before the cast keeps the unsigned result meaningful.
396        let health = health.max(0);
397        // The `.min(100)` is DEFENSIVE, not measured: `health > maxhealth`
398        // occurs 0 times in 677 health-bearing rows, so no test pins it and
399        // a mutation removing it survives. It stays because a percentage
400        // above 100 would be nonsense in a gauge -- but it is an assumption
401        // about the wire, not a fact from it.
402        Some(((health.unsigned_abs() * 100) / max).min(100))
403    }
404
405    /// Is this status set?
406    ///
407    /// `false` both when the frame said it is off and when the frame did not
408    /// mention it. Use [`Self::stated`] to tell those apart.
409    #[must_use]
410    pub fn is(&self, status: Status) -> bool {
411        self.statuses.get(&status).copied().unwrap_or(false)
412    }
413
414    /// Is this classification set?
415    #[must_use]
416    pub fn is_classified(&self, class: Classification) -> bool {
417        self.classifications.get(&class).copied().unwrap_or(false)
418    }
419
420    /// **Did this frame mention the status at all?**
421    ///
422    /// The three-valued answer: `Some(true)` set, `Some(false)` sent as `0`,
423    /// `None` not mentioned -- the wire as it was. A `<crtrStatus>` is a
424    /// **snapshot** of the flags it can carry: the game lists what is active
425    /// and leaves out what is not (a stunned creature's next tag has no
426    /// `stunned`, not `stunned='0'`), so for those flags not mentioned is off.
427    /// [`CreatureInstance::sync_crtr_status`] applies it that way.
428    ///
429    /// [`CreatureInstance::sync_crtr_status`]: crate::state::creatures::CreatureInstance::sync_crtr_status
430    #[must_use]
431    pub fn stated(&self, status: Status) -> Option<bool> {
432        self.statuses.get(&status).copied()
433    }
434
435    /// Did this frame mention the classification at all?
436    #[must_use]
437    pub fn stated_classification(&self, class: Classification) -> Option<bool> {
438        self.classifications.get(&class).copied()
439    }
440
441    /// **Is this creature unable to act?**
442    ///
443    /// Any set status that stops it acting. The question a hunting consumer
444    /// asks before deciding whether a
445    /// room is safe to loot in.
446    #[must_use]
447    pub fn is_muckled(&self) -> bool {
448        self.statuses
449            .iter()
450            .any(|(status, &on)| on && status.is_muckle())
451    }
452
453    /// Is this a worthwhile target: hostile, and not already dead?
454    ///
455    /// Not dead, and hostile. Both are here because a caller asking "should I
456    /// attack this" wants one answer.
457    #[must_use]
458    pub fn is_attackable(&self) -> bool {
459        self.is_classified(Classification::Hostile) && !self.is_classified(Classification::Dead)
460    }
