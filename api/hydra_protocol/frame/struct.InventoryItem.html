Expand description

One <i> row from an <inventoryManager> snapshot: a single item.

The rows are assembled into Frame::InventoryManager with their envelope; apart, the inventory tree the response exists to deliver would never be assembled.

§<i> is an item, not italics

On HTML instinct <i> would be styling beside <b>, and every row here would degrade to Frame::Structural with its attributes trapped in a raw string. In recorded sessions every <i> is inside an <inventoryManager>, and none is italics (see parser::markup::is_markup).

§What the wire states

In recorded sessions (~149 items a snapshot):

grep -ohE '<inventoryManager [^>]*>.*' *.xml ///   | grep -oE '<i [^>]*>' | grep -oE '[a-z_]+=' | sort | uniq -c
#  5364 id=   5364 loc=   5364 name=   5364 weight=
#  1044 long=  468 in_max=   72 on_max=    36 flags=

So id, loc, name and weight are on every row and the rest are not. encum, in_encum, in_selector, locker and familyvault have not been seen but are read too, because the same feed can carry them and an attribute we do not read is one we silently drop.

Fields§

§id: String

id=: the item’s exist id.

§relation: String

loc=, split: where the item sits relative to Self::parent.

worn,player -> ("worn", "player"); in,309585704 -> ("in", that container); the bare room -> ("room", "room").

In recorded sessions about four in five are in,*; the rest are worn,*.

§parent: String

What Self::relation is relative to: player, room, or a container’s exist id.

§name: String

name=, rejoined for display: "a scorched glowbark long bow".

§article: String

name=’s first comma field. May be empty.

§adjective: String

name=’s second comma field. May be empty.

§noun: String

name=’s third comma field, or the whole value when it does not split into three – losing the item is worse than an odd noun.

§long: Option<String>

long= with its $_ emphasis markers stripped, when stated.

§weight: Option<i32>

weight= in pounds. None when unstated.

Signed, and -1 is a sentinel meaning the item cannot be picked up – room furniture and fixtures. See Self::can_pick_up.

§encum: Option<i32>

encum=: an encumbrance override, -1 for a fixed item.

§in_max: Option<u32>

in_max=: packed contents capacity. Decode with Self::in_capacity.

§on_max: Option<u32>

on_max=: packed surface capacity, same encoding.

§in_encum: Option<u32>

in_encum=: pounds currently inside, when the server reports it.

§in_selector: Option<String>

in_selector=: a noun phrase to address the container by instead of its id (lockers and similar).

§locker: bool

locker="1".

§familyvault: bool

familyvault="1".

§flags: Vec<String>

flags=, comma-split. Observed: closed (36 rows, all on a purse).

§other: Vec<(String, String)>

Every attribute the wire sent that no field above reads, as (name, value) in wire order: one the wire grows is kept, not dropped.
