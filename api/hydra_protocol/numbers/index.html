current/max extraction from a progress bar’s text= attribute.

§Two traps

A simple splitter gets two things wrong:

health -10/125  pct=0   -> (10, 125)     // sign discarded
health -1/125   pct=0   -> (1, 125)
health 213/223  pct=95  -> (213, 223)    // correct
numbed          pct=90  -> (90, 100)     // max fabricated
  1. The sign is discarded. Splitting on non-digits makes -10 into 10. A character at -10 health – dying – reports as +10, and anything watching health concludes the character is fine while they bleed out. So Amount::current is i32.
  2. A maximum is invented. Answering a label-only bar (text='numbed') with (percentage, 100) gives a max the wire never sent, indistinguishable from a real one. So the return is Option: absent means absent.

The value= attribute does not rescue either case – it is a percentage (text='health 213/223' ships value='95'), and at negative health it reads 0. The number the caller wants lives only in text=.
