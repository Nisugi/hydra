The line transducer: bytes in, Frames out.

§Why hand-rolled and not an XML library

The wire has no root element. It is an unbounded sequence of fragments, and several tags are mode switches with no close: a corpus sample of 5,079,826 tags measured 23,328 <style ...> opens and zero </style> closes, plus <output class="mono"/> / <output class=""/> as an open/close pair that is self-closing at both ends. A tree-building parser must either error or invent structure, and this parser never errors on unknown input.

The malformations that would justify a tolerant library are absent. In that same sample: 0 tags split across a newline, 0 unquoted attribute values, 0 tags opened without a > on the line. The wire is well-lexed even though it is not well-formed. A substring scanner is sufficient, and sufficient is the simplest answer.

§The read boundary

A Parser consumes whole lines and never sees a TCP fragment. The socket reassembles with read_until(b'\n') before decoding, which is correct: the measurement above says the line is a safe frame boundary on this wire. read_until on bytes rather than read_line on a String is also load bearing – the stream is CP1252, and read_line returns InvalidData on any non-UTF-8 byte, which would hard-disconnect a client.

Parser::push_bytes implements that reassembly here, so the rule is enforced by this crate rather than assumed of its caller, and so a test can drive a split at every byte offset.

A tag with no > before the line ends is not prose. Appended to the text buffer, it would silently desync parser state. Here it is Frame::MalformedTag: typed, logged, rendered.

§MULTI-LINE CAPTURES: measured, and deliberately not built

Buffering a <compDef>/<component>/<inv> whose close tag is on a later line, accumulating until the close arrives, is not built, on evidence:

$ grep -h -cE '<(compDef|component|inv)[^>]*>[^<]*$' <272 stratified files>
0                       # opens with no close on the same line
$ grep -h -o '<compDef' <same files> | wc -l
447095                  # opens in total

and, driving the parser over 60 of those files, 1,230,355 wire lines with no such open. Two years of traffic does not contain the case.

Such a buffer would also be a black hole. Bounded by MAX_LINE_BYTES of accumulated body, which is not a bound on frames lost, at a realistic 60-character line it would swallow 4,297 consecutive lines of game text before the cap fired – 3,236 at 80 characters, 1,019 at 256. Only a <prompt> would break it sooner. That is a multi-thousand-line silent-loss risk for a case the wire has never produced.

An unclosed paired tag is Frame::MalformedTag, same as any other tag with no terminator: typed, surfaced, and bounded to its own line. Upgrade trigger: if the corpus replay ever reports a MalformedTag whose raw begins <compDef, <component or <inv, the wire has started sending this and a buffering path is needed – bounded by lines, two or three, not by bytes.

§The prompt as a resync barrier

At every <prompt>, force-close open streams and drop orphaned markup. It is what makes the push/pop imbalance harmless – the corpus has 19,142 pushStream against 14,714 popStream, because pushStream is not a stack discipline. Prompts are frequent (207,626 in the sample), so this bounds all state corruption to one round.

§What this parser does NOT do

It does not drop lines that look like GSL framing by their first letters. A rule that drops any line beginning GS + a lowercase letter also swallows "GSrule violations are handled by the GameMasters." and "GShaldi the merchant nods at you." – ordinary game prose, silently discarded. Hydra talks to the game directly, so the case is live. GSL framing, when needed, must key on the \x1C prefix that actually marks it.
