Strip Lich’s HH:MM:SS: line prefix.

The XML in a Lich .xml log is the wire – Lich does not rewrite tags – but it prefixes some lines with a local clock. That prefix is not wire traffic, and a fixture keeping it teaches the parser a lie: 01:46:11: <component id='room objs'>a rock</component> parses as a spurious Text("01:46:11: ") frame followed by the component.

Removing it is a better answer than skipping such files: most logs carry the prefix on some lines, and taking only files with zero timestamped lines would discard most of them to avoid a ten-character prefix.

The exact shape is HH:MM:SS: – the third colon belongs to Lich’s format, then exactly one space. Recorded logs carry this form and never HH:MM:SS without the trailing colon, so there is one form and this is it.

Anchored at the start of the line, and only there. A timestamp inside prose (“meet me at 01:46:11: sharp”) is display text the game sent, and stripping it would edit the wire rather than unwrap it.

The second shape. A newer Lich build writes a full date and a spelled-out zone instead:

2026-09-01 15:13:58 Central Standard Time: <component id='room objs'>...

on nearly every line of its logs, always at the start of the line.

The two shapes come from different Lich builds, which is why they are not folded together.

Without this rule those logs are unusable as fixtures, and the failure mode is the one the HH:MM:SS: docs above record: a prefixed line yields Text("2026-09-01 15:13:58 Central Standard Time: ") ahead of the real component. That is a fact the game never sent, baked into a golden.
