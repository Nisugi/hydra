hydra

Module instance 

Source
Expand description

Hydra runs once on a data folder at a time.

The first process to start holds hydra.lock in the data folder, locked for as long as it runs. The system lets the lock go when the process ends, however it ends, so a crash leaves nothing to clear away.

The first also listens on a loopback port for another launch asking it to open its windows, and writes the port and a key to hydra.port. Not into the lock file: on Windows another process cannot read a locked file.

A second launch finds the lock held, says the key and open on that port, and leaves: the windows open in the process already running, or its hub comes to the front when they are open already, shown again if it was closed.

Hydra starting fresh starts the next process before it leaves, and that one waits for the lock to be let go (claim_once_left), and for the web page’s port (until_free).
