Hydra’s command line.

hydra                                                             the hub
hydra login <character> [--account <account>] [--game <code>]   raw stream
hydra play  <character> [--account <account>] [--game <code>]   readable text, `;status`
hydra gui   [<character>... | <character> [--account <account>] [--game <code>]]   the hub
hydra serve [<character>... | <character> [--account <account>] [--game <code>]] [--detach] [--in <dir>] [--web <port>]
                                                                  resting, no window
hydra replay <file.bytes|file.xml> [--summary | --text]

--detach leaves the console and rests in the background, its log in the data folder (startup.rs); --in runs Hydra from that directory; --web serves the web page on that port for the run, whatever its setting. --again, --open and --resume are for Hydra’s own use: starting fresh, it starts the next process with --again; restarting, with --open as well, the hub opened at once, and a --resume for each character to start again (gui.rs).

Modules§

attention 🔒
A highlight’s sound, speech and notification, played on a thread of its own: the audio device is opened, and lives, on one thread; so does the computer’s voice.
connect 🔒
hydra login: log one character in and show the raw game stream.
gui 🔒
hydra, hydra gui and hydra serve: Hydra’s own process, every character on a supervised session in one host table, and its windows whenever they are wanted.
instance 🔒
Hydra runs once on a data folder at a time.
play 🔒
hydra play: one character in the terminal, on a supervised session.
render 🔒
Frames to plain terminal text: what the dumb client shows.
replay 🔒
hydra replay <file>: run a recording through the parser and print the frames.
rest 🔒
Hydra between its windows: the computer kept awake while a character plays, and what Hydra holds in memory, written to the log each time what it is doing changes, and every minute while characters play. A build with measure says what each part of Hydra holds as well (hydra_mem).
started 🔒
How long Hydra takes to start, stage by stage, written to its log: the wall clock as main began, then each stage with the time since, up to the first frame the windows draw. A start that is slow on one computer says in its log where the time went, before main ran included: that is the clock’s first line against the moment Hydra was asked for.
startup 🔒
Hydra starting on its own: hydra serve --detach, which leaves the console and rests in the background; on Windows, the sign-in entry that runs it; and Hydra starting fresh, which starts the next process so, with --again (rest).
status 🔒
;status: one line of what the game state holds right now.
terminal 🔒
A terminal opened by Hydra itself: hydra-tui in a console window of its own, on a character shown in a terminal as it starts, or on the hub from the tray.
tray 🔒
Hydra’s icon in the Windows tray, for as long as it runs, its windows open or not.
update 🔒
Hydra updating itself (hydra_update): a newer release looked for as Hydra starts and every six hours while Check for updates is on, said on the hub and in the tray, and fetched when either asks for it, or as soon as it is found with Update on its own on. Fetched, it is in place of the program running, and runs from Hydra’s next start: when Hydra starts fresh, or is started again.

attach_console 🔒
The terminal Hydra was started from, if any, taken as its own: without a console of its own, login, play and replay would say nothing. Started by a double click there is none, and nothing is opened.

hydra chunks learn: each game’s chunk kinds learned afresh from every recording in the logs folder, with Hydra stopped – a Hydra running holds the tables it learned and would write them over what this learned.
lookout_seed 🔒
hydra lookout seed: every day of the player logs not yet taught to the lookout, taught, with Hydra stopped – a Hydra running holds the lookout it learned and would write it over what the seeding learned.
