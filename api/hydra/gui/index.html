hydra, hydra gui and hydra serve: Hydra’s own process, every character on a supervised session in one host table, and its windows whenever they are wanted.

Hydra runs once on a data folder at a time (instance). Another launch on it opens the windows of the process running, and leaves.

Hydra rests between its windows: its characters play on, the web page is served while its setting is on (hydra_web::serve), and the computer is kept awake while a character plays (rest). On Windows its icon is in the tray throughout (tray). hydra serve starts it resting; hydra and hydra gui open the windows at once. The windows take the main thread while they are open, so the sessions and their feeds run on the runtime’s workers.

Characters named on the command line start at once, their passwords asked at the terminal when none is kept; the hub and the web page start the roster’s. Closing the hub hides it while another window is open, and once none is the windows close and Hydra rests. Its Shut down, or Ctrl-C, stops every character in order: quit to each, a wait for the game to close each connection, then the sessions end. A second Ctrl-C leaves at once.

Rested long enough with nothing playing, Hydra starts fresh (rest::until_fresh): it starts the next process in the background, resting, and leaves, the lock held to its end; the next waits for it to go. A web page a team started for the web had is served by the next as well. A page open on a phone loses its connection for a moment and finds the next by itself. An update fetched (update) is the program the next process starts as.

Each character’s session runs on a runtime of its own, two threads (game_runtime), apart from the windows’, the page’s and the rest of Hydra’s.

The hub’s Restart now, once an update is fetched, shuts Hydra down in order as Shut down does and starts the next process the same way, but with the hub open, and, if the player kept the box ticked, the characters that were playing started again, each with its team (Table::resume).
