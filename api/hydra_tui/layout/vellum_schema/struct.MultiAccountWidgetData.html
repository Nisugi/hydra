Expand description

Multi-account cards: which rows each character’s card shows.

Every element is opt-in per field rather than a fixed card template, because what matters differs by playstyle – a healer wants dolls, a caster wants mind state. Defaults are the four that answer “is this character in trouble right now”: vitals, RT, status glyphs and the group.

Fields§

§show_vitals: bool

Health/mana/stamina/spirit bars.

§show_rt: bool

Roundtime and casttime, interpolated from the peer’s own clock.

§show_status: bool

Compact colored glyph row (stunned, bleeding, hidden, …).

§show_injuries: bool

Injury doll per card, drawn with YOUR installed doll art and the peer’s reported wounds. Peers ship an injuries map, not art, so a character using custom doll art shows on yours – sending each peer’s variant and calibration is a later addition.

§show_mind: bool

Mind state bar.

§show_stance: bool

Combat stance bar.

§show_field_exp: bool

Unabsorbed field experience, with a warning when at or near the cap – the point of watching it is knowing when to go absorb.

§show_encumbrance: bool

Encumbrance bar.

§show_room: bool

Room name, and the “not with you” cue when it differs from yours.

§show_self: bool

Include a card for this character, sorted first and accent-marked. On by default: without it a group of three shows only two cards, and the others have nothing to be compared against.

§show_absolute_vitals: bool

Show absolute vitals (“51/51”) instead of percentages, where the peer has reported them. Percentages remain the fallback.

§show_hands: bool

Hands, and the spell being prepared.

§show_effects: bool

Debuffs and cooldowns, filtered by effect_filter.

§effect_categories: Vec<String>

Which effect categories to draw, in order. Defaults to the two that answer “is this character in trouble” – active spells and buffs are long lists that would bury the card.

§effect_filter: Vec<String>

Case-insensitive substrings; an effect shows only if its name contains one of these. Empty means show everything in the chosen categories.

A filter rather than a fixed list because effect names vary by profession and society, and a hardcoded set would be wrong for somebody. Empty-means-all keeps the first run useful: you see everything, then narrow it.

§max_effects: usize

Cap on effects drawn per card, after filtering. Six characters with unbounded lists is unreadable regardless of the filter.

§merged_rows: Vec<String>

Rows drawn on the same line as the row above them, by row id.

Short rows waste a full line each: RT is one label and the status icons are a compact strip, so they pair naturally. Defaults to pairing those two, which is the combination every card wants.

§row_order: Vec<String>

Row order within a card, top to bottom. Names match the toggles: “status”, “vitals”, “rt”, “hands”, “effects”, “mind”, “stance”, “field_exp”, “encumbrance”, “injuries”. The room id is not a row – it renders in the card header, gated by show_room.

Rows not listed are appended in their default order, so an old config (or a partial list) still shows everything – a missing name hides nothing, it just does not reposition it.

§card_column_weights: Vec<f32>

Relative widths of the card’s row columns; the LENGTH is the column count. [1.0] (default) is the classic single vertical panel; [1.0, 1.4] is a doll column with a wider info column beside it. Same idea as the window Group system’s size weights.

§card_row_columns: BTreeMap<String, usize>

Row id -> column index (0-based). Rows not listed sit in column 0; indices past the last column clamp to it, so shrinking the column count never hides a row.

§sort_by: String

Card order: “group” keeps clustered characters together (default), “name” sorts alphabetically, “port” is connection order.

§columns: usize

Cards per row before wrapping. 0 means fit as many as the window is wide enough for.

§card_width: f32

Card width in points.

pub fn ordered_rows(&self) -> Vec<(CardRow, bool)>

Rows in display order, paired with whether each is shown. Rows missing from row_order keep their default position, so a partial list never hides anything – the checkbox is what hides.

Whether a row is currently enabled. Exhaustive: a new row cannot ship with a checkbox that silently toggles nothing.

Source

Enable or disable a row.

Source

pub fn row_merge_flag(&self, row: CardRow) -> bool

Raw membership in the merge set – what the config STORES. The editor reads and writes this; only the renderer applies the positional “first row cannot merge” rule. Conflating the two was a data-loss bug: the view snapshot read the positional answer (false for whatever row was first) and wrote it back on any unrelated edit, deleting the stored flag.

Source

pub fn row_merged(&self, row: CardRow) -> bool

Whether this row RENDERS on the line above it: stored flag, unless the row is first (nothing above it to join).

Source

pub fn set_row_merged(&mut self, row: CardRow, merged: bool)

Set or clear a row’s merge-with-above flag.

Source

pub fn column_weights(&self) -> Vec<f32>

Column weights sanitized for layout: at least one column, every weight positive. Garbage in the config degrades to equal columns rather than a zero-width or vanished one.

Source

pub fn row_column(&self, row: CardRow) -> usize

Which column a row renders in, clamped to the columns that exist – an assignment to a removed column lands in the last one instead of hiding the row.

Source

pub fn set_row_column(&mut self, row: CardRow, column: usize)

Assign a row to a column. Column 0 is the default, so assigning it removes the entry rather than storing a redundant zero.

Source

pub fn row_lines(&self, column: usize) -> Vec<Vec<CardRow>>

One column’s rows grouped into lines: each inner vec is one horizontal run. Order within the column follows row_order.

Hidden rows are dropped BEFORE grouping, so hiding the row a merged row was attached to promotes it to its own line rather than leaving a dangling continuation. The same applies to rows moved to another column: “share line with the row above” chains only within a column.

Source

pub fn move_row(&mut self, row: CardRow, up: bool)

A row moved one place up or down, the whole order written out first so an empty row_order becomes the order it stood for.
