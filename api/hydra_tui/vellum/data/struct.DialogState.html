§dropdowns: Vec<DialogDropDown>

Option pickers (<dropDownBox>), e.g. combat stance/aim/spell.

§links: Vec<DialogLink>

Text-command links (<link>), e.g. combat’s skin/search footer.

§images: Vec<DialogImage>

Icon buttons (<image>), e.g. combat’s weapon-ready row.

§skins: Vec<DialogSkin>

Backdrop art (<skin>), e.g. UberBar’s injury paperdoll + bar skins.

§spinboxes: Vec<DialogSpinBox>

Integer spinners (<upDownEditBox>), e.g. quickstrike offset.

§declared_size: Option<(f32, f32)>

Content size the game DECLARED (openDialog width/height, px; 0 = unset), captured from WindowHints. The anchor grid’s vertical compass (align e/w/c center-referenced, s bottom-referenced) resolves against the declared height; without it those aligns are taken from the top.

§position: Option<(u16, u16)>

Manual position override (None = auto-center)

§size: Option<(u16, u16)>

Manual size override (None = auto-size based on content)

§save_position: bool

Whether to persist position/size across sessions (save=‘t’ in XML)

pub fn positioned_controls( &self, ) -> Option<(Vec<PositionedControl>, (f32, f32))>

Resolve buttons/dropdowns/progress bars to pixel rects using the game’s layout language: absolute top/left interpreted through compass align (nw = from left, n = from horizontal center, ne = from right), then anchor_top/anchor_left/anchor_right constraints re-positioning controls against resolved siblings (offsets add to the anchored edge; anchor_left + anchor_right together stretch the control between them). Returns None when no control carries position data — callers fall back to flow layout. Anchor references to controls we don’t capture (images) are skipped, leaving that axis at its absolute placement.
