The ledger: what Hydra records of play, kept across sessions.

One SQLite file, hydra.db at the top of the data folder, holds every character’s rows; each row names its instance and character. Hydra is one process, so one Writer serves every session: recorders hand it rows over a channel and a thread of its own writes them, in short transactions, so no game thread waits on the disk. Reports open a Reader, read-only.

  • row: the rows, as the tables hold them.
  • writer: the writing thread and the handle recorders hold.
  • reader: the read-only side the reports use.

The schema is versioned in SQLite’s user_version; Ledger::open applies every migration not yet applied, in order.
