Expand description

What the page is told.

Variants§

§

Welcome

The pairing was right: the page is answered from now. login: whether it may log a character in, which a page on the device Hydra runs on may.

Fields

§login: bool

The login form is answered.

§

Refused

The pairing was wrong, or never said: the socket closes.

Fields

§why: String

Why, for the page to say.

§

Hotbars

The character’s hotbars, each button as it looks now; and why a file of them does not read, when one does not.

Fields

§bars: Vec<BarOut>

The bars, in the files’ order.

§problems: Vec<String>

What is wrong with the files.

§

Themes

The themes a page can wear, by name.

Fields

§names: Vec<String>

Every theme: the built-in ones, then the themes folder’s.

§

Theme

The colours the page wears, by token name, #rrggbb: the window’s, or the theme the page chose.

Fields

§colors: BTreeMap<String, String>

Every token’s colour.

§names: BTreeMap<String, String>

The colours the theme gives lines by their names, each name as a run carries it (css_name).

§prompt: BTreeMap<String, BTreeMap<&'static str, String>>

Each prompt character’s look (prompt_looks).

§

Hub(HubOut)

The hub: every character seated, and those that can be started.

§

Attached

The character the page asked for is shown.

Fields

§id: u32

Its session’s number.

§name: String

Its name.

§game: String

Its game’s code.

§streams: Vec<StreamOut>

The streams read alongside the story, which the page offers a chip for and can keep out of the story.

§story_lines: usize

How many of the story’s lines the page keeps.

§stream_lines: usize

How many of each stream’s lines the page keeps.

§

Detached

The character shown is no longer on the table.

Fields

§why: String

Why, for the page to say.

§

Lines

The story’s lines from line from on: the page keeps the lines it has before from, and puts these after them. A from past what it has means lines were lost between.

Fields

§from: u64

The first line’s number in the story.

§lines: Vec<Line>

The lines.

§

View(Box<View>)

What the play page shows beside the story.

§

Menu

An object’s menu, as the game answered it.

Fields

§noun: String

What was tapped.

§groups: Vec<MenuGroupOut>

Its entries, in groups.

§

Offer

A link the game sent for something the page asked – the skill manager, for goals web – offered for a tap, as a page cannot open one itself unasked.

Fields

§text: String

What the link is, for the page to say.

§url: String

The link, play.net’s.

§

Said

Hydra’s answer to something the page asked.

Fields

§text: String

The answer.

§

Wheel

The character’s touch wheel, without its commands; none when its controller files have no wheel.

Fields

§wheel: Option<TouchWheel>

The wheel.

§

Banners

The shown character’s banners, a highlight’s alerts, as they float over the page: sent again when one comes or goes, or the Banners page changes.

Fields

§banners: Vec<BannerOut>

The banners, oldest first.

§across: &'static str

Where across: left, centre or right.

§down: &'static str

Where down: top, middle or bottom.

§width: f32

Its width, a share of the page’s.

§opacity: f32

How solid it is.

§ground: Option<String>

Its ground, #rrggbb; none, the theme’s warning colour.

§text: Option<String>

Its words’ colour, #rrggbb; none, what reads on its ground.

§

Stream

A stream’s lines from line from on, as Out::Lines are.

Fields

§id: String

The stream.

§from: u64

The first line’s number in the stream.

§lines: Vec<Line>

The lines.

§

Workspace

The answer to a workspace request, as an HTTP answer would be.

Fields

§ask: u32

The request’s number.

§status: u16

200, 404 for none kept, 412 for a newer one kept (in body), 400 or 413 for one refused, 500 for one that could not be read or written.

§body: Option<String>

The workspace kept, when there is one to say.

§

Highlights

Every highlight, for the page’s editor.

Fields

§categories: Vec<CategoryOut>

The categories, by name.

§rules: Vec<RuleOut>

The highlights, by name.

§sounds: Vec<String>

The sounds a highlight can play, by file name.

§

Doll(Box<DollOut>)

The injury doll’s body, once a character is shown.

§

Inventory(Box<InventoryOut>)

The shown character’s inventory, while the page’s is open.

§

Tasks(Box<TasksOut>)

The shown character’s bounty and objectives, while the page’s tasks are open.

§

Trainer(Box<TrainerOut>)

The shown character’s skill trainer, while the page’s is open.

§

Notes(Box<NotesOut>)

Every note, while the page’s notes are open.

§

HighlightsText

The highlights file as this computer keeps it, and when it last changed, seconds since the epoch.

Fields

§text: String

The file’s text.

§changed: Option<u64>

When it last changed, seconds since the epoch; none, never.

§

Phone

What this computer keeps as the phone’s kind, and when it last changed, seconds since the epoch; nothing, with none kept.

Fields

§kind: String

Which of the phone’s files: buttons, wheel or ui.

§text: Option<String>

The file’s text; none, with none kept.

§changed: Option<u64>

When it last changed, seconds since the epoch; none, with none kept.

§

PushPaired

The phone is paired for push: the id this desktop is known by, which each alert names for the tap to open.

Fields

§desktop: String

This desktop’s id.

§

Highlighted

What a change the page asked of the highlights did.

Fields

§done: bool

It was made.

§text: String

What was done, or why not.

§kept: Option<String>

The highlight kept, by its name, when one was saved.
