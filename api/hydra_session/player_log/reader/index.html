hydra_session::player_log

The player log’s reader.

Day listing, the tail, a time window, and literal or regex search, over the files super::writer leaves: <root>/player/<character>/<character>_<day>.log, one format_line per line.

§Off the actor, always

Every function here is plain blocking file I/O and touches no session state. One task owns every session’s socket, so a synchronous multi-file scan there would freeze EVERY connected character at once. A caller in async code runs these on a blocking task, and asks the writer to flush first (PlayerLog::flush), or a search of the live session misses its last second.

§A time window is a time window

window compares stamps; it never counts lines back from the end. A window approximated by a line count falls short: an 8,000-line tail reaches back 6.2 minutes of a requested 11 when a busy character logs ~820 lines a minute. The stamp is HH:MM:SS.mmm, fixed width, so within a day text order IS time order, and the day is the file’s.

§Bounded

At most MAX_HITS lines come back from any read, and at most MAX_DAYS files are opened by one. A read that stopped at the cap says so (Found::more).

§Plain or archived, one day

A day is read from wherever its files are: plain .log files, or members of a month’s or a week’s archive (super::archive). Only days and read_day know there is a difference.

Functions§

around
The lines of day around the first written at at under tag saying text: up to radius lines before it and as many after, as they were written, and where it is among them. None when the day holds no such line.
days
Every day this character has a log for, YYYY-MM-DD, newest first.
export
Write every line from the days from to to (both kept, YYYY-MM-DD) kept by streams to one plain file at out, oldest first. The caller gives the range and the streams; this does all the I/O. At most MAX_DAYS days, the newest dropped past that.
export_path
Where an export of from to to goes when the player names no place: exports/ in the character’s log folder, which no read of the log looks in.
read_day
One day’s lines, in the order they were written; none for a day with no file.
read_day_from
read_day, and how far its plain files were read; or, from tail, a read before, only the lines written since, as a day being played adds them. An archive holds only closed days, so is read only when the day is read whole.
search
The lines whose text matches pattern, kept by streams, newest first, from the days on or after since (every day when None): the first MAX_HITS found, over at most MAX_DAYS days.
search_days
The lines whose text matches pattern, kept by streams, newest first, from the days from to to (both kept, YYYY-MM-DD): one page, at most MAX_HITS lines from at most MAX_DAYS days, starting where resume, the last page’s, says. Where the next page starts is said when there is more.
sort_again
entries read back as the stream rules sort them now: a line of the game’s written with no class, before a rule that takes it was made, takes the class the first rule a past line can be tried by gives it (Compiled::sort_past), as a line sorted as it came is written: main becomes main/ambients. A command, Hydra’s word, or a line written with a class is left as it is; the files are never changed.
tagged
entry after its time, as an export writes it and as a copy of the line takes it: its tag as parts asks ([cmd/lich], [lich], none), then its text. One form, so a copy and an export of the same lines read alike.
tail
The last count lines kept by streams, oldest first, across as many days as it takes (at most MAX_DAYS). count is capped at MAX_HITS.
window
The lines from from up to but not including to, kept by streams, oldest first: the first MAX_HITS of them, with Found::more set when there were others after.
