hydra_session::player_log

Module feed 

Source
Expand description

One connection’s feed into the player log: what is captured, and what a line is tagged once its chunk is understood.

A goal of the log is a combat feed separable from the main feed: with enough definitions, a blob is classified as combat when it contains one of them.

§A line’s class is not known when the line ends

The blob is the model’s prompt-to-prompt chunk, and the combat tracker classifies it when the prompt closes it. So the feed holds a chunk’s lines and writes them at the prompt, when the actor can say whether the chunk produced combat facts. Everything is held, not only the main window’s lines, so the file stays in the order things happened; each line keeps the stamp of the moment it arrived.

§The tag: source/class

A line from a combat chunk is tagged main/combat. The class never replaces the source: main is where the game sent it, combat is what our definitions made of it. A chunk the definitions miss stays main.

§Capture is configurable because a feed costs disk

Capture decides what is WRITTEN; filtering what is SHOWN is the reader’s. Every feed is available. The readouts – streams the game clears and rewrites whole – default to off, and when on are written only when they change. A character’s choice of feeds is its settings file’s (LogSettings), from the settings menu’s Player log page.

Constants§

COMBAT
The class given to every main-window line of a chunk that produced combat facts.
MAX_HELD
A chunk is written unclassified once it holds this many lines: the login burst and a long look in a crowded room run far past anything a combat chunk does, and a connection that never prompts must not hold its log in memory.
SECTION
The name of LogSettings’ section.
