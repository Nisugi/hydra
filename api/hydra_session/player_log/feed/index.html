hydra_session::player_log

Module feed 

Source
Expand description

One connection’s feed into the player log: what is captured, and what a line is tagged once its chunk is understood.

A line is tagged where the game sent it, and after that where the stream rules put it (crate::stream_rules): the built-in rule puts each main line of a chunk with fighting in it in combat, so the combat feed reads apart from the rest.

§A line’s class is not known when the line ends

The blob is the model’s prompt-to-prompt chunk, and the combat tracker classifies it when the prompt closes it. So the feed holds a chunk’s lines and writes them at the prompt, when the actor can say whether the chunk had fighting in it and which lines the reader marked. Everything is held, not only the main window’s lines, so the file stays in the order things happened; each line keeps the stamp of the moment it arrived.

§The tag: source/class

A line from a combat chunk is tagged main/combat. The class never replaces the source: main is where the game sent it, combat is what the rules made of it. A line no rule matches stays main. A command, a readout, is never sorted.

§Every feed a player reads is written

Capture decides what is WRITTEN; what is SHOWN is the reader’s choice alone. A player has no choice of what is written: a feed left out is a hole no reader can fill, and the feeds cost little beside the story. The readouts – streams the game clears and rewrites whole – are left out, the connection’s recording keeping them; a capture that asks for one writes it only when it changes.
