Writing a file Hydra keeps – a character’s facts, the learned menu dictionary, a layout, a doll’s calibrated picture – so it is never left half written, and naming a character’s file.

Here rather than in a frontend, since the session keeps files too.

Functions§

changing
Run change – a read of the file at path, a change, and its write – with no other change to that file in this process made meanwhile: two settings changed at once must not each read the file, and the second write lose the first change. A lock per file; not reentrant.
character_path
<dir>/<instance>_<character><suffix>; None when either half has nothing a filename can carry, rather than two such characters sharing one file.
safe_component
A name from the wire as one path component: its ASCII letters and digits, lowercased, so Ashryn and ASHRYN are one file on every platform. Character names are alphanumeric, so filtering loses nothing.
save_bytes
Write bytes to path in dir, atomically: to a temp file of this write’s own, synced, then renamed over path. Two writes of one file at once never rename each other’s half-written temp into place.
save_json
Write value to path in dir as JSON, atomically (save_bytes).
