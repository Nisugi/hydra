Module character_store 

Source
Expand description

A character’s facts on disk: what info, skills, the PSM lists, wealth and the rest taught, kept so a restart does not show a character with no stats until someone types them again.

The shape on disk is hydra-model’s [CharacterSnapshot]; this is the filesystem and when to touch it.

§One file per character, by instance and name

<data>/<instance>_<character>.json

Both halves: two characters of one name on different instances are different characters.

§Read once a session, at <app>

The file is named after the character, and the name arrives with <app> partway into the login burst. Once per session, not per connection: <app> comes again on a reconnect, and a second read would put the disk’s older values over what the session learned since.

§Written five minutes after it stops changing

Writes are queued and done in bulk, five minutes after the last change. A group taught pushes the write out to five minutes from then; a sync teaches every group within a second and they collapse into one write. A connection’s end writes what is waiting, whatever the clock says.

What is stored is merged into what was: a group this session never taught keeps the stamp an earlier one wrote.

§A refused file is a character never synced

A file from another SCHEMA_VERSION, or naming another character, is refused rather than read; the model stays empty, as for a character never stored, and the ordinary commands fill it again.
