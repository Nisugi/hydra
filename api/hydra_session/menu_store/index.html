Module menu_store 

Source
Expand description

The learned menu dictionary on disk: one supplemental TSV for every character, beside the table Hydra ships.

Nothing prunes it: a save writes only rows the shipped table lacks, so a release that absorbs them empties the file at the next push anyway.

§One file, rewritten whole

The file is global: every character gets the same command list. When another push comes in, the file is rewritten with the existing rows plus the new, under the new timestamp. A coordinate’s meaning is a fact about the game, and every character receives the same push, so the file is one and always is the answer: load, merge the push, write back.

§Written the moment a push arrives

The server pushes <cmdlist> when it decides the client is behind, not on every connection, so a crash must not lose one. A push is rare (once in a month of logs, measured), so the write costs nothing.

§Read when a session starts

A session starts from the file, so a learned row helps every session after the one that heard it, not only that one.

§The shipped table’s format

coord label command category under that header, as hydra-model/data/menu_commands.tsv, so folding the file back into the shipped table is a concatenate and sort. The version is a leading # cmdtimestamp comment.

Functions§

load
The dictionary kept in dir; empty when there is none, which is the ordinary state of an install whose shipped table is current. A row that cannot be looked up – too few columns, no coordinate – is skipped rather than the whole file refused.
merge_and_save
Fold session’s rows – what one push taught – into the file in dir: load, merge, write back, its version winning, with no other change to the file made meanwhile (crate::store::changing). None when nothing is novel, and then no file is left: a server that restores a command to its shipped value must not have the old override come back after a restart.
store_path
Where the dictionary is kept in dir.
underlay
learned, a session’s, with the rows kept in dir under it: what the session heard wins over what the file says, and the file’s version stands until the session hears one.
