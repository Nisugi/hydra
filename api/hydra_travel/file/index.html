hydra_travel

Source
Expand description

The travel file, <data>/travel.json: what travel remembers, and the names the player gave rooms.

The travel settings are not kept here: they are on the character’s Travel page (crate::settings).

{ "schema_version": 3,
  "targets":    { "bank alley": [7120] },
  "characters": { "GS3_Nerten": { "memories": {…}, "targets": { "my shop": [228] },
                                  "last_room": 228 } } }
  • A character’s spot: what earlier crossings wrote down (memories: which town Duskruin was entered from), where it was last known to be (last_room), and its own targets.
  • The top-level targets are everyone’s, on every instance: a person running one session or twenty-five wants the same shortcuts for every character. A character’s own name is looked for first.

Places the map names – bank, town – are not kept here: they are the map’s tags (crate::route::destination).

§Never written over when it cannot be read

This is what Hydra did and what the player chose, which the game never teaches again: a lost memory strands a character at an event, since the way back is priced on it. So a file that cannot be read, or that a newer Hydra wrote, is refused and left alone, and a schema change migrates.

§Many characters, one file

Nothing here writes back the file it read. A save changes one thing – one character’s spot, or one target – by reading the file afresh, changing that, and writing it back, under the file’s lock (hydra_session::store::changing).
