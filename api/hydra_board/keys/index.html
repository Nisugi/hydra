Module keys 

Source
Expand description

Keybinds: a key, and the macro it does on the character whose window has the keyboard – commands sent as if typed there, text put in the command input, or one of Hydra’s actions (crate::binding).

Hydra’s defaults live in the code (defaults.rs); the keybinds file holds only what the player added or changed, a key written "" unbinding a default. A character’s own keys file goes over it, and each holds ten macro sets (file).

A key is named by its winit code – Numpad8, F13, KeyA, ArrowUp – with ctrl+, shift+, alt+ or cmd+ before it. The physical key, not the character it types, so a binding means the same key on every keyboard layout, and a numpad key is never its digit. A key that types – a letter, a digit, a mark, with no Ctrl, Alt or Cmd – never fires a binding, or nobody could type it.

NumLock is nobody’s. On Windows and Linux it is the operating system’s switch for the numpad; on macOS, which has none, winit calls the Clear key NumLock, and Clear is Hydra’s switch there, the numpad typing or sending its keys.

Modules§

file
A keys file read: every character’s, the keybinds file in the data folder, or one character’s own beside its settings. Both hold the ten macro sets, set 0 under [keys] and the others under [set1] to [set9]; every character’s holds the numpad’s switch too, and a character’s the set it has chosen:
vellum
Vellum’s keybinds read: a keybinds.toml of Vellum’s – its global one, a character’s, or a named set – into Hydra’s set 0, since Vellum has no macro sets.
wizard
A Wizard front end macro file read: each line of a profile’s .Mac into a key of Hydra’s set 0, the Wizard having one set.
wrayth
A Wrayth key set read: the <macros> of a Wrayth settings file, each of its ten sets (<keys id name>, its keys <k key action/>) into the Hydra set of the same number. No XML crate: the file is Wrayth’s own flat shape.
write
The keys files’ writer: every character’s keybinds file, and a character’s own. The Keys page’s changes are made one at a time to a file’s text, a line at a time, so what a player wrote there by hand – a comment, the order – is kept. The result is read back first: a file this cannot change in place, a [keys] written as an inline table say, is refused rather than mangled.

repeats
Whether a held key’s repeats do made again. A send does, as holding a direction keeps walking; so does an action that steps – scrolling, the history, the next window, tab, line found or target – as a held arrow keeps moving. A switch does not, so a held one ends where one press leaves it: a macro set, the Find bar, a drawer, Lock, Arrange, a character’s window. Nor does a fill, which would only write the same words over.
types
Whether the key of this name types something when pressed. A bound key that does is taken with what it typed: egui sends a letter’s text beside its press unless Ctrl or Cmd is held, so Alt+C did its macro and typed a c as well.
