hydra_board

Module store 

Source
Expand description

Writing the files the windows keep – a layout, the windows’ places, the hotbars, what was typed – in batches, off the window’s thread, so a frame never waits on the disk and a file is never left half written: the session’s own write ([hydra_session::store]).

A batch is a fixed time. The first change starts it; every change made until it ends is written when it ends, together; it is never pushed back. A change after that starts the next. Of several changes to one file in a batch, each is made in order and the file written once: a whole file asked for replaces what came before it, and an edit is made to the file as it then stands.

A window shows its change at once; the file follows. While a change to a file waits, the window does not take a read of that file over its own (pending). Hydra closing writes what waits first (flush).

Under test, each change is written at once, so a test reads what it wrote.

Constants§

BATCH
How long a batch gathers changes before they are written: a minute, so a disk is written to at most once a minute while Hydra is played. What a crash or a pulled plug takes is at most that minute’s changes; Hydra closing writes them first.
