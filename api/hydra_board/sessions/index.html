Module sessions 

Source
Expand description

What the binary and the window share: every character seated, and what the hub shows of the roster, and the way the hub asks the binary for something.

The binary owns the session table and the roster: it seats a character as it starts one, unseats one it takes off, and tells the board the roster, the characters it can start, and an account’s listing. The hub asks it through [HubControl], and the answer is shown for a while.

The web page reads the same board: the colours the window wears, and whether the page is wanted and on which port, which the window sets from its own settings, a team started for the web asks for besides, and the page’s server follows (Sessions::web_wanted); the server says where it listens, or why it does not, for the hub.

The binary also says here how the windows are opened (Sessions::opener): the session table asks for them so, with or without the hub, when a team starts with its play windows; and for a terminal of its own on a character shown in one.

Hydra’s own settings (window.toml, Own) are held here once, for every front end: a change one makes is the one every other sees, and none writes back what it held before. What Hydra has to tell the player with no character to tell it to – a file that would not write, highlights that cannot be used – is said here (Sessions::tell), and every hub shows what it has not shown yet.

And where an update of Hydra is (Update): the binary looks for one and fetches it, the hub and the tray say where it is, and either asks for it to be fetched (Sessions::fetch_update).
