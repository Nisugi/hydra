Module push 

Source
Expand description

Push to phone: a trigger’s alert sent to each phone paired for it, as a banner from HydraFE, through the push relay (hydra-push).

Pairing. A phone already paired with the page says its device token, whether it is a build run from Xcode (Apple’s sandbox), a name, and a sealing key it made. The desktop keeps them in push.json in the data folder, with its own id, the one the phone knows it by, and its token from the relay, asked for the first time a phone pairs.

Sealing. Each alert is sealed for its phone with that phone’s key, ChaCha20-Poly1305, laid out as Apple’s CryptoKit lays a sealed box: a 12-byte nonce, the ciphertext, the 16-byte tag, as base64. The relay and Apple see only that. The app opens it on the phone and shows the title and text, and a tap opens this desktop on the character.

Sending is a task of its own, never waited on: a relay down or slow holds no character up. A phone whose token Apple says is gone is forgotten; a desktop token the relay no longer knows is asked for again, once, however many pushes found it so (desktop_token). An alert is cut to fit a push before it is sealed (fitted).

Forgetting. A page pairs its phone each time it connects, so a phone forgotten by .push forget is remembered by its key, and its pairing turned away until .push allow takes it again.
