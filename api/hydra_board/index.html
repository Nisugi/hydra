The board: what Hydra’s windows, its web page and its binary share, with no window toolkit in it.

Every character seated (Sessions, Seat): what its feed heard and its last snapshot, and the way to send it a line; the highlights its story looks through; the hotbars and the controller’s wheel as their files say, which the window and the page both resolve; and the files Hydra keeps for each character, read and written off the caller’s thread. Whatever draws the board wakes through Wake, which it fills in while it is open.

Modules§

banner
Banners: a highlight’s alert, and Hydra’s own, shown over the play window and the web page while they last. Where they float, how wide, how solid, their colours and how long they stay are Hydra’s to say for every character, on Settings’ Banners page: the [banner] table of Hydra’s own settings file.
binding
What a key does: a macro is a keybind that sends one or more commands to the game, fills the command input, or performs one of Hydra’s actions.
chips
Effect chips: a chip is a small summary of the effects it gathers, a mark and a few words, coloured by how soon the first of them runs out. Each chip is a widget of its own, shaped by the player: which of the game’s lists it gathers, whether the player’s own timers and the effects tracked as missing, and any effect by name, so one spell can be a chip. The window and the page draw the same chips from the same layout file; the gathering here is what both show.
clip
What the player copied in the story, given its links back: the copied text is plain, so each of its lines is found again among the story’s lines, whose runs say what each word links to. A line the story does not hold – part of one, or one long gone – is kept as plain words.
disk
Files the windows read, read off their thread: the window never waits on the disk.
highlights
The highlights every character’s story looks through, shared between the window, which reads the file when it changes, and each character’s feed, which builds its own from them; and the desk that plays their sounds and shows their notifications, and what Hydra calls attention to beside them: an Ebon Gate merchant opening, told once however many characters hear it.
hotbars
A character’s hotbars as its files have them, and what a button sends: for the web page, and for .hotbar in every frontend.
kept
Where each character’s files are kept, and a file that would not read kept aside rather than written over.
lookout
The lookout’s page among Hydra’s own in the settings menu: its choices, kept in lookout.toml in the data folder for every character (hydra_lookout::settings), taken by every session at once.
macros
A character’s macros (hydra_ui::macros): the files they come from, read as the hotbars are, and a macro’s chain in the character’s world, for a key, a button, .macro and the page alike.
merchants
An Ebon Gate merchant opening for business, called to the player’s attention as Hydra’s General page says: a banner in the window of each character the game tells, and a notification from the computer once, however many characters it tells.
own
Hydra’s own settings, one set for every character, kept in the window’s own file, window.toml in the data folder.
pad
A game controller’s file (controller.toml): every character’s in the data folder, a character’s own beside its layout over it. What each button and wheel slice does, read here for the window’s pad and for the web page’s touch wheel alike.
push
Push to phone: a trigger’s alert sent to each phone paired for it, as a banner from HydraFE, through the push relay (hydra-push).
seat
One character as its windows see it: what its feed heard and the last snapshot, and the way to send it a line.
sessions
What the binary and the window share: every character seated, and what the hub shows of the roster, and the way the hub asks the binary for something.
store
Writing the files the windows keep – a layout, the windows’ places, the hotbars, what was typed – in batches, off the window’s thread, so a frame never waits on the disk and a file is never left half written: the session’s own write ([hydra_session::store]).
stream_rules
The stream rules every character’s session sorts its lines by (hydra_session::stream_rules), held by the board for every session it starts, and read from their file in the data folder again when it changes, once a second at most, off the window’s thread (crate::disk). An editor’s change (change) is made to them at once, and to the file with the next batch of saves.
targets
The Targets list, as the window’s widget and the page’s panel both show it: which creatures in the room are targets, and the look the player chose for them on the widget’s page, read from the character’s layout file so the page shows what the window shows.
trainer
One character’s skill trainer: what GOALS was asked for, and the skill manager it opened.
