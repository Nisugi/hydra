Crate hydra_import 

Source
Expand description

A recording read back into the ledger.

A .bytes file is one session’s wire, both directions, with the chunk boundaries the live session had; a long session is several parts, -000, -001 and on, that concatenate to the one stream. The import replays a session through the parser and the model as the session did, each closed chunk’s combat facts into the combat recorder and each mind-state bar into the exp tracker, every row stamped by the prompt’s own time. Nothing is ever sent to a game.

§Lich’s logs

Lich writes the same wire, game to client, as .xml files under logs\<GAME>-<Name>\, named by when each began: GSIV-Nisugi\2026\01\ xml\2026-01-03_12-28-32.xml. The folder names the character and its game (GSIV is Prime), and the file the stamp. Each file opens and closes with a date line of Lich’s own, not the game’s, both left out. Lich cuts a login into files by size, and only the first holds the login burst: a file without one is the next part of the session before it, so a hunt across the cut stays one hunt.

§Never twice

  1. A session imported is noted by its character and stamp, and refused the next time.
  2. A session whose span touches a hunt or a pulse already on file for that character, one Hydra recorded live, is refused by name.
  3. A pulse at a time with a total already on file is skipped.

import

instance_of
The instance the login burst names, by its text alone: <app ... game="Prime" ...> says it outright; failing that, the code in <settingsInfo instance='GS3' ...> mapped, when Hydra knows the code. The wire’s own code for Prime is GS4, which the table does not carry, so the app tag comes first.
lich_name_of
A Lich log’s character, game code and stamp: 2026-01-03_12-28-32.xml under a GSIV-Nisugi folder is Nisugi on GS3, at that stamp. Lich’s code for Prime is GSIV; its others are Hydra’s own.
name_of
GS3_Nisugi-2026-10-14_02-53-24-000.bytes as its game code, character and stamp; the older Nisugi-2026-10-01_23-16-16-000.bytes with no code.
sessions
The sessions among paths: each a .bytes file or a folder searched whole, grouped by character and stamp, oldest first.
span_of
The first and last prompt times in bytes, by their text alone, so a session’s span is known before anything is written.
