ReplaySource: the second ByteSource implementor, which plays a recorded session back.

A recorded session replays deterministically in a test, with no network. This type touches no socket, no DNS and no TLS – it cannot reach a network, rather than being asked not to.

§Chunk boundaries are the point

chunks is a list of the byte slices each live read returned, not one concatenated buffer. Replaying the same split exercises Parser::push_bytes’s pending-fragment path with a boundary that really occurred. Re-chunking would quietly test a different thing than what ran.

§What it does with writes

It keeps them. A replay has no peer to answer, so a write cannot change what comes back – the recording already fixed that. Keeping them is what lets a test assert the session sent what it was asked to, which is how “every command goes through the same queue” is observed without a game.
