LiveSource: the TCP+TLS ByteSource, the transport a real login uses.

§No test reaches a real host

No test in this workspace calls LiveSource::connect against a real host, and none may: logging into the live game service is done by hand. One test calls it against a LOOPBACK listener in its own process (tests/keepalive.rs), to read back the socket options it sets – nothing leaves the machine.

§Async, and why

Every await here is cancellable. A blocking read is not: set_read_timeout is a timeout, not a cancellation, and a 250ms stop is unreachable from inside one.

§Three facts about the servers this relies on

  1. One write per message. Two write_all calls can emit two TLS records and this server does not tolerate a command split across them. Encoded in ByteSource::write_all’s contract and honoured below.
  2. native-tls, not rustls. eaccess negotiates TLS 1.2 static-RSA key exchange (0x009c), which rustls refuses to implement. Verified by packet capture.
  3. The game socket is not the eaccess socket. A login connects to eaccess over TLS for the handshake, then opens a plain TCP connection to the game host and sends the key. This type is the second of those: the session’s byte source is the game stream, which is not TLS. LiveSource::connect_tls exists for the eaccess half, and is reachable only through the certificate pin (eaccess/pin.rs).

The game stream has a second route: the WebSocket shim on 443 (LiveSource::connect_shim, shim.rs), which IS TLS – verified TLS, unlike eaccess. It is the fallback when the game port is unreachable.
