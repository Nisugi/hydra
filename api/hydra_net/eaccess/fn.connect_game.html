Open the game socket and send the three-part handshake.

This is the second connection: plain TCP, not TLS, to the host and port the LaunchPayload names. The eaccess socket is already closed by the time this is called.

The handshake is key, then banner, then two <c> ready signals once the game is ready for them:

  1. {key}\n – the one-shot key from L.
  2. CLIENT_BANNER – which selects the extended feed. See that constant: it is not cosmetic.
  3. Wait for the game’s <settingsInfo>, which says it is ready.
  4. Two <c> signals, ~300ms apart.

What the game sent while the handshake waited is not lost: the GameSource returned reads it first, as if it had just arrived.

§The <c> signals, and why they are sent

The game server expects two <c> signals with a delay between them. An A/B run against the live server settled whether they matter:

runresult
with the signals2,347 bytes – full login burst: room, exits, inventory, exposeContainer
without163 bytes – stops at <settingsInfo>

So they are not required to log in, and required to be usable. Both runs “connect”; only one produces a session worth having. Connected is not working, which is why the pass criterion is game text, not a TCP accept.

§Waiting for <settingsInfo> before sending them

Sent on a timer from the banner, the signals can arrive before the game is listening for them, and are lost: the game stops at <settingsInfo> as if they were never sent, and waits for the player’s first command. Recorded: a team of four logged in within one second, and three stopped there; on another day, two of three. Every team whose logins were a second or more apart got through. The game takes longer to validate logins that arrive together, and <settingsInfo> is its word that it is ready. Should it never come, the signals go after 30 seconds (READY_WAIT), as they did before.

§The endpoint fallback

The connect is tried twice when the endpoint has a known second spelling: connect_with_fallback below has the detail, and gemstone::endpoint records why the table is a fallback rather than a pre-emptive rewrite.

§Errors

EaccessError with stage game_connect or game_handshake.
