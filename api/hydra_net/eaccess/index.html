Module eaccess 

Source
Expand description

The EAccess login handshake: account and password in, game host and key out.

docs/eaccess-spec.md describes the protocol. The sequence is K A M F G P C L over one TLS connection, and its product is a LaunchPayload – a plain TCP host, a port, and a one-shot key.

§Why this is in hydra-net

Nothing in this module knows what a Frame is, which is exactly the line the crate’s own header draws around this layer. EAccess speaks tab-delimited fields over TLS and stops the moment the game socket opens; it never sees game markup. LiveSource::connect_tls is here for its transport, and native-tls is a dependency of this crate for the same reason.

The cost is stated rather than hidden: the hydra binary calls down to hydra-net directly, past every layer between them. The alternative, a login inside the session crate, would put a protocol the session does not otherwise speak inside it, and make the login unrunnable without first constructing a session.

§Async, and why the refusals are specific

The I/O runs on LiveSource, so every wait is cancellable; a read timeout is not a cancellation. Each refusal in the handshake turns a failure that would point somewhere else into one that names its own cause.

§No test logs in

A test must not log into the live game service. No test here calls authenticate, and none may.

§Layout

wire is the pure half: the types that cross the wire and the functions that read its fields. Every one is covered by tests/eaccess_wire.rs, because a live login is a terrible place to find an off-by-one. handshake is the half that touches a socket. Its connect is checked only by running it live; its conversation is tested. handshake::converse runs K A M F G P C L over any ByteSource, and handshake_tests.rs drives it against a scripted AnsweringSource – because some defects (the key trimmed at the call site, an M refusal that is not fatal, an L quoted unredacted) sit in exactly the code a pure-function test cannot see. pin opens the TLS connection and checks its certificate against the stored pin before handshake may send anything on it – trust on first use, and a FATAL refusal on change rather than a silent re-pin.
