Expand description

The password hash: ((pw[i] - 32) ^ key[i]) + 32, in i32.

§Why this refuses instead of wrapping

14,336 of the 65,536 byte pairs hash outside 0..=255. Rust u8 wraps there in release and panics in debug. No login is known to have successfully sent a byte outside 0..=255, so the server’s behaviour there is completely unobserved. Masking with & 0xFF would emit bytes no server has been seen to accept: an untested protocol change.

It also closes the short-key case. Rust’s zip would silently stop at the shorter of the two, producing a wrong password rather than an error.

§Errors

EaccessError with stage hash if the key is shorter than the password, or if any byte falls outside 0..=255.

Only the first is fatal. Whether a byte falls outside the range depends on the key, and the key is the server’s, new with every attempt: a password with a byte above ASCII fails some keys and passes others. Fatal, it would stop the retries and skip the web login, which takes the password as typed. Transient, the next attempt draws a new key and the fallback is tried.
