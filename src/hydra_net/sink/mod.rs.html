1//! Where a session's **wire** traffic goes to live on disk.
2//!
3//! # This is one of two logs, and it is the lower one
4//!
5//! A session has two kinds of log: this development log of the wire, and a
6//! user log of the processed text.
7//!
8//! | | this file | the user log |
9//! |---|---|---|
10//! | content | raw bytes, both directions, chunk boundaries | display text as a player reads it |
11//! | audience | developers: debugging, and cutting fixtures | the player: "what happened in that hunt" |
12//! | layer | `hydra-net`, **below** the parser | needs `Frame`s, so **above** it |
13//! | lifetime | churn freely | kept; searched years later |
14//!
15//! **The user log cannot live in this crate.** Processed text does not exist
16//! until `hydra-protocol` has parsed it, and `hydra-net` is below
17//! `hydra-protocol`. So it is not an extension of this type -- it is a
18//! different type at a different layer, and [`SessionSink`] is named for the
19//! wire rather than for logging in general so that it does not squat on the
20//! name the other one wants.
21//!
22//! [`Recorder`](crate::record::Recorder) holds one session's wire bytes in
23//! memory and is what a replay test replays. It is **pure** -- no clock, no file
24//! handle, `seq` seeded at 0 -- and that purity is what makes a replay of a
25//! replay byte-identical. This module is the other half: the part that writes,
26//! kept separate so the recorder stays deterministic.
27//!
28//! # Why the recorder does not own a file
29//!
30//! Giving `Recorder` a `File` would put I/O, a path, and a failure mode inside
31//! the type every replay test constructs. The tests would then either touch
32//! the filesystem or carry a null-writer branch that production never takes.
33//! A sink the session flushes to costs one field and leaves the replay tests
34//! free of I/O.
35//!
36//! # What lands on disk
37//!
38//! **`.bytes` is the point.** It is the raw wire with chunk boundaries
39//! preserved: replay input, and the source fixtures should be cut from.
40//! Everything a session did is in here already, in the form the server sent
41//! it.
42//!
43//! `.log` is a **debug log**, and it is small on purpose:
44//!
45//! | File | Holds | For |
46//! |---|---|---|
47//! | `<char>-<stamp>.bytes` | the raw wire, both directions | replay, cutting fixtures |
48//! | `<char>-<stamp>.log` | lifecycle and errors -- things that are **not** on the wire | why a session did something |
49//!
50//! # What `.log` must NOT become
51//!
52//! **A timestamped text mirror of the wire.** `.bytes` is the whole point, and
53//! duplicate timestamped lines add nothing to it.
54//!
55//! In particular `.log` does not hold commands: a command is wire content and
56//! is already in `.bytes`, sent exactly as the server received it. Writing it
57//! again in another format makes two sources of truth for one fact and
58//! doubles the disk for nothing.
59//!
60//! The formatted, timestamped, human-readable view of a session **is the user
61//! log**, which is a different artifact at a different layer (see above) and
62//! is not this.
63//!
64//! # This is a PRIVATE development log
65//!
66//! Credentials are scrubbed exactly (see [`Redactions`]): the account name,
67//! the account holder's real name and the session key are known before or
68//! during the handshake, so removing them is exact rather than heuristic.
69//!
70//! **Other players' names are NOT scrubbed, and this file does not pretend
71//! otherwise.** `hydra_protocol::scrub` deliberately refuses to guess which
72//! capitalised word is a person -- "`Inochi` and `Rawknuckle's` are the same
73//! shape, one is a player and one is a tavern" -- and a live session has
74//! nobody to name them in advance. So a session log is safe from the
75//! *credential* angle and is still **not automatically shareable**. Cutting a
76//! fixture out of one goes through `Scrubber` with the names named.
