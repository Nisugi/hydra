1//! The byte source: where a session's wire bytes come from.
2//!
3//! # Why this is a trait
4//!
5//! It has real implementors that are needed today, not one implementor and a
6//! guess at the future: [`LiveSource`](crate::live::LiveSource) is the game
7//! connection, [`ReplaySource`](crate::replay::ReplaySource) plays a recorded
8//! session back deterministically in a test **with no network**, and
9//! [`AnsweringSource`](crate::answering::AnsweringSource) stands in for the
10//! game in tests.
11//!
12//! # Why it yields BYTES, not lines and not frames
13//!
14//! **Lines would duplicate work that already exists.**
15//! `Parser::push_bytes` (in `hydra-protocol`) is the read boundary: it buffers
16//! until a newline, so a tag split across two TCP reads is rejoined before
17//! parsing. Its own doc says so, and the split-at-every-byte-offset test lives
18//! beside it. A line-yielding transport would reimplement that reassembly one
19//! layer down, in a place no test drives at every offset.
20//!
21//! **Frames would invert the layers.** The parser lives in `hydra-protocol`,
22//! which sits above this crate. A transport that yielded `Frame` would need
23//! `Parser` *below* the crate `Parser` lives in.
24//!
25//! So: bytes. Chunk boundaries are whatever the source gives, which is exactly
26//! what makes replaying a recording exercise the partial-line path for real.
27//!
28//! # Why not `AsyncRead + AsyncWrite`
29//!
30//! Considered and rejected. A replay source would have to impersonate a
31//! socket, and `AsyncWrite::shutdown` conflates "the recording ended" with
32//! "the peer hung up", which a clean disconnect has to tell apart.
33//!
34//! # Deadlines are the caller's
35//!
36//! Every wait has a deadline. That deadline is applied by the session with
37//! `tokio::time::timeout`, not taken as a parameter here: a timeout belongs to
38//! the *policy* that waits, not to the pipe. Passing one in would be a config
39//! option with one caller.
40
41use std::future::Future;
42use std::io;
43
44/// A source of raw wire bytes for one session.
45///
46/// `Send` because each session runs as one supervised task, and a task's
47/// future must cross threads on a multi-thread runtime.
48pub trait ByteSource: Send {
49    /// Read the next available chunk into `buf`.
50    ///
51    /// `Ok(0)` means end of stream: the peer hung up, or the recording ran
52    /// out. It is not an error: a clean disconnect (the task ends, no socket
53    /// leaks, nothing panics) is the *normal* end of a session, so it must not
54    /// arrive as an `Err`.
55    fn read(&mut self, buf: &mut [u8]) -> impl Future<Output = io::Result<usize>> + Send;
56
57    /// Write one whole message, as **one** write.
58    ///
59    /// Two `write_all` calls can emit two TLS records, and the server does not
60    /// tolerate a command split across records. That is why this method takes
61    /// the finished message rather than offering a `write` plus a
62    /// `write_newline`.
63    fn write_all(&mut self, message: &[u8]) -> impl Future<Output = io::Result<()>> + Send;
64
65    /// Close the source. **Idempotent**, because no socket may leak and the
66    /// session shuts down on several paths -- cancellation, end of stream,
67    /// and read error -- which must not be mutually exclusive.
68    fn shutdown(&mut self) -> impl Future<Output = io::Result<()>> + Send;
69}
