1//! Classifying an `A` response that carried no session key.
2//!
3//! Split out of [`handshake`](super::handshake) because it is pure -- it takes a
4//! string and returns a verdict -- and the handshake around it needs a socket.
5//! That is the same seam [`wire`](super::wire) already draws.
6//!
7//! # Two cases wearing one answer
8//!
9//! Treating every `A` response without `\tKEY\t` as **fatal**, full stop,
10//! would collapse two situations the supervisor must tell apart:
11//!
12//! | The server said | It means | Retrying |
13//! |---|---|---|
14//! | `REJECT`, `NORECORD`, `INVALID`, `PASSWORD` | the credentials are wrong | pointless, and risks the account |
15//! | anything else | we do not know what happened | is the only way back |
16//!
17//! Fatal is right for the first and **wrong for the second**, in the direction
18//! that strands a session: a garbled reply during an unattended reconnect
19//! permanently stops a client whose credentials are good. `wire.rs` itself calls
20//! that direction unsafe; the other direction, hammering the auth server with
21//! a wrong password, could lock the account. Both hazards are real and they
22//! point opposite ways, which is exactly why the two cases cannot share a
23//! verdict.
24//!
25//! # The raw body of an unrecognised reply is NOT logged
26//!
27//! The `A` response can be a real rejection token or an unrecognised,
28//! garbled response, so only the derived classification is logged, not the
29//! raw text. An unrecognised response is exactly the case most likely to
30//! contain something unexpected -- an HTML intercept page from a WAF, a
31//! truncated fragment -- that cannot be assumed safe to log verbatim.
32//!
33//! A **recognised** token is still printed: it is a short protocol word, it is
34//! the most useful thing a reader can be told, and it is not a secret. So the
35//! rule is not "never print the response" -- it is "print what you recognised".
36
37/// The rejection words the server sends.
38///
39/// These are observed server behaviour, not a guess at what it might say.
40const KNOWN_REJECTION_TOKENS: &[&str] = &["REJECT", "NORECORD", "INVALID", "PASSWORD"];
41
42/// What an `A` response with no session key turned out to be.
43#[derive(Clone, Debug, PartialEq, Eq)]
44pub enum Rejection {
45    /// The server named a rejection we recognise: the credentials are wrong.
46    ///
47    /// Carries the token, which is safe to print and is the single most useful
48    /// thing to tell whoever is reading the failure.
49    Credentials(String),
50    /// The server said something we do not recognise.
51    ///
52    /// **No body.** It is the case most likely to be a WAF intercept page or a
53    /// truncated fragment, and a length is all a diagnostic needs.
54    Divergence {
55        /// Length of the unrecognised response, in bytes.
56        bytes: usize,
57    },
58}
59
60impl Rejection {
61    /// Whether retrying could ever succeed.
62    ///
63    /// `false` for [`Self::Credentials`] -- the same credentials will be
64    /// rejected again, and each attempt is another strike. `true` for
65    /// [`Self::Divergence`], because "we do not know what that was" is not
66    /// evidence the credentials are wrong, and a client that stops on it
67    /// strands a session that a retry would have recovered.
68    #[must_use]
69    pub const fn is_fatal(&self) -> bool {
70        matches!(self, Self::Credentials(_))
71    }
72}
73
74/// Classify an `A` response that carried no `\tKEY\t`.
75///
76/// Matched with `contains` rather than an exact compare: the response is
77/// tab-delimited and the token arrives as a field, so requiring the whole
78/// string to equal it would recognise nothing.
79#[must_use]
80pub fn classify_a_rejection(response: &str) -> Rejection {
81    let upper = response.to_ascii_uppercase();
82    KNOWN_REJECTION_TOKENS
83        .iter()
84        .find(|token| upper.contains(*token))
85        .map_or_else(
86            || Rejection::Divergence {
87                bytes: response.len(),
88            },
89            |token| Rejection::Credentials((*token).to_owned()),
90        )
91}
