1//! What persists between sessions, and how it goes stale.
2//!
3//! The model half. The I/O half is the session's character store; this file
4//! is the **shape** on disk and nothing else, so `hydra-model` stays free of
5//! the filesystem.
6//!
7//! # The store is the primary record, not a cache
8//!
9//! It is persisted, in parts. A command run by hand populates it, ordinary
10//! play keeps it updated (training sends its own report), and there is a way
11//! to reset and refresh it.
12//!
13//! That is the design constraint. Most of what is here can only be taught by a
14//! command a person runs by hand -- `info`, `skills`, the five PSM lists,
15//! `inventory enhancive totals`. A model rebuilt each session would show a
16//! character with no stats until someone typed `info`, so the file on disk is
17//! the record and the wire merely updates it.
18//!
19//! It is also why [`Group`] exists. "Reset and refresh" needs to know **which**
20//! group is stale, and a single whole-file timestamp cannot answer that: a
21//! character who ran `skills` this morning and `info` last month has one fresh
22//! group and one ancient one.
23//!
24//! # Why serde and not a database
25//!
26//! The access pattern does not want a database. Every read is "give me this
27//! character's stats"; there are no queries, no joins, and one writer. Typed
28//! fields serialize as they are.
29//!
30//! # Staleness is a version AND a timestamp, per group
31//!
32//! **A parser change invalidates stored values**, so a snapshot written by
33//! an older [`SCHEMA_VERSION`] is not trusted: the classifier that produced
34//! it may have read a column differently.
35//!
36//! A per-group timestamp plus a schema version is both halves: the version
37//! answers "can this file be believed at all", and the per-group stamp
38//! answers "which command should be re-run".
39

52/// The format version of a written snapshot.
53///
54/// **Bump this whenever a classifier changes what it stores**, not only when a
55/// field is added or removed. A snapshot is the output of a parser, so a parser
56/// that starts reading a column differently invalidates every file written
57/// before it.
58///
59/// An older snapshot is not migrated. It is **refused**, which puts the
60/// character back to "never synced" and lets the ordinary sync repopulate it.
61/// Migration code for a format nobody has shipped is a premature
62/// abstraction; when there is a second version and real files to migrate, that is
63/// the time to write it.
64pub const SCHEMA_VERSION: u32 = 1;

66/// Which command taught a group, and therefore which one refreshes it.
67///
68/// **The grouping is by SOURCE COMMAND, not by subject.** `Stats` and
69/// `Identity` are separate groups even though both come from `info`, because
70/// Shroud of Deception falsifies the identity while leaving the numbers alone
71/// (`blocks.rs`'s `classify_identity`) -- so they can genuinely be fresh and
72/// stale at different times.
73#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Serialize, Deserialize)]
74#[serde(rename_all = "snake_case")]
75pub enum Group {
76    /// The ten statistics, from `info` or `info full`.
77    Stats,
78    /// Race, profession, gender, age -- also `info`, but separately staleable.
79    Identity,
80    /// The 46 skills and the spell circles, from `skills`.
81    Skills,
82    /// The five PSM tables, each from its own `<category> list all all`.
83    Psms,
84    /// Enhancive totals, from `inventory enhancive totals`.
85    Enhancives,
86    /// Silver, notes and the event currencies.
87    ///
88    /// Its own group because it goes stale on its own schedule: silver changes
89    /// with every purchase while skills change when you train.
90    Currency,
91    /// Society, citizenship, warcries and resources.
92    ///
93    /// **The one group ordinary play keeps current.** The others are only
94    /// ever taught by a command someone runs; this one is also taught by
95    /// living in the world -- you join a society, you train a PSM, and the
96    /// game says so unprompted. See `standing.rs`.
97    Standing,
98}
99
100impl Group {
101    /// All seven.
102    pub const ALL: [Self; 7] = [
103        Self::Stats,
104        Self::Identity,
105        Self::Skills,
106        Self::Psms,
107        Self::Enhancives,
108        Self::Standing,
109        Self::Currency,
110    ];
111
112    /// Every command that teaches this group, in send order.
113    ///
114    /// **Not one command.** [`Self::refresh_command`] answers with the single
115    /// most representative one, which is right for "refresh this" in a menu
116    /// and wrong for a sync: `Psms` needs six `<category> list all all` and
117    /// `Standing` needs four unrelated reports. A sync that sent one per group
118    /// would leave five of the six PSM tables empty and still stamp the group
119    /// fresh.
120    ///
121    /// Commands this model does not yet read (`profile full`, `spell`,
122    /// `experience`) are not sent; they arrive with the classifiers that
123    /// consume them.
124    #[must_use]
125    pub const fn sync_commands(self) -> &'static [&'static str] {
126        match self {
127            // One report teaches both, and sending `info full` twice would
128            // double the traffic to learn nothing.
129            Self::Stats | Self::Identity => &["info full"],
130            Self::Skills => &["skills full"],
131            Self::Psms => &[
132                "armor list all all",
133                "cman list all all",
134                "feat list all all",
135                "shield list all all",
136                "weapon list all all",
137                "ascension list all all",
138            ],
139            Self::Enhancives => &["inventory enhancive totals"],
140            Self::Standing => &["society", "citizenship", "warcry", "resource"],
141            // `wealth` states silver; `tickets` states every event balance in
142            // one report. Without them a character who has never run them
143            // reads as unknown until ordinary play says otherwise, which is
144            // honest, and filling that in is what a sync is for.
145            Self::Currency => &["wealth", "tickets"],
146        }
147    }
148
149    /// The command that refreshes this group.
150    ///
151    /// Here rather than in the session layer because it is a fact about the
152    /// game, and because "reset and refresh" needs it: a caller asking to
153    /// refresh a stale group should not have to know the command by heart.
154    ///
155    /// [`Self::Psms`] answers with one of five; the caller sends all five, and
156    /// `PsmSet` is already keyed per category so a partial refresh is
157    /// meaningful.
158    #[must_use]
159    pub const fn refresh_command(self) -> &'static str {
160        match self {
161            Self::Stats | Self::Identity => "info full",
162            Self::Skills => "skills full",
163            Self::Psms => "cman list all all",
164            Self::Enhancives => "inventory enhancive totals",
165            // One of four, like `Psms`: `citizenship`, `warcry` and
166            // `resource` each teach a different part. `society` is the one a
167            // caller refreshing a single group most likely means.
168            Self::Standing => "society",
169            Self::Currency => "wealth",
170        }
171    }
172}

174/// Everything about one character that survives a restart.
175///
176/// **Not `GameState`.** What is here is what a command taught and what no
177/// reconnect re-sends: the room, the hands, the vitals and the prompt are all
178/// re-sent by the login burst (`reconnect.rs` measures which), so persisting
179/// them would store a belief about a session that has ended.
180#[derive(Debug, Clone, Default, PartialEq, Eq, Serialize, Deserialize)]
181pub struct CharacterSnapshot {
182    /// The format this file was written in. See [`SCHEMA_VERSION`].
183    pub schema_version: u32,
184    /// The instance, from `<settingsInfo instance=>`.
185    ///
186    /// **Part of the identity, not decoration**: two characters of the same
187    /// name on different instances are different characters.
188    pub instance: String,
189    /// The character's name, from `<playerID>`.
190    pub character: String,
191    /// The ten statistics.
192    pub stats: BTreeMap<StatKind, Stat>,
193    /// Race, profession, gender, age.
194    pub identity: Identity,
195    /// The 46 skills and the spell circles.
196    pub skills: SkillSet,
197    /// The five PSM tables.
198    pub psms: PsmSet,
199    /// Enhancive totals.
200    pub enhancives: EnhanciveTotals,
201    /// Silver, notes and the event currencies.
202    pub currency: Currency,
203    /// Society, citizenship, warcries and resources.
204    pub standing: Standing,
205    /// When each group was last taught.
206    ///
207    /// Absent means never. `BTreeMap` rather than five `Option` fields so
208    /// iterating the stale ones is a loop rather than five hand-written arms.
209    pub updated_at: BTreeMap<Group, SystemTime>,
210}
211
212impl CharacterSnapshot {
213    /// A snapshot for a character nothing has taught yet.
214    #[must_use]
215    pub fn new(instance: &str, character: &str) -> Self {
216        Self {
217            schema_version: SCHEMA_VERSION,
218            instance: instance.to_owned(),
219            character: character.to_owned(),
220            ..Self::default()
221        }
222    }
223
224    /// Take a snapshot of what a live character has been taught.
225    ///
226    /// **The timestamps are the caller's**, not `SystemTime::now()`: only the
227    /// caller knows which groups this write is recording as fresh, and a
228    /// snapshot that stamped every group on every save would report a group as
229    /// current when nothing had re-taught it.
230    ///
231    /// `instance` and `character` come from the wire (`<settingsInfo>` and
232    /// `<playerID>`) rather than from the character, because they identify the
233    /// FILE and a character does not know its own filename.
234    #[must_use]
235    pub fn of(
236        character_name: &str,
237        instance: &str,
238        character: &super::Character,
239        updated_at: BTreeMap<Group, SystemTime>,
240    ) -> Self {
241        Self {
242            schema_version: SCHEMA_VERSION,
243            instance: instance.to_owned(),
244            character: character_name.to_owned(),
245            stats: character.stats.clone(),
246            identity: character.identity.clone(),
247            skills: character.skills.clone(),
248            psms: character.psms.clone(),
249            enhancives: character.enhancives.clone(),
250            currency: character.currency,
251            standing: character.standing.clone(),
252            updated_at,
253        }
254    }
255
256    /// Restore what a stored snapshot knows into a live character.
257    ///
258    /// **Only the persisted groups are touched.** Everything else on a
259    /// `Character` -- stance, encumbrance, injuries, the `expr` experience --
260    /// is connection state that the login burst re-sends, and overwriting it
261    /// from a file would replace a fresh fact with an old one.
262    ///
263    /// Refused outright when the schema version does not match, for the reason
264    /// [`Self::is_current`] gives: a file written by a different classifier may
265    /// have read a column differently, and reading its fields as if they meant
266    /// what they mean here is the error the version exists to prevent.
267    pub fn restore_into(&self, character: &mut super::Character) -> bool {
268        if !self.is_current() {
269            return false;
270        }
271        character.stats.clone_from(&self.stats);
272        character.identity.clone_from(&self.identity);
273        character.skills.clone_from(&self.skills);
274        character.psms.clone_from(&self.psms);
275        character.enhancives.clone_from(&self.enhancives);
276        character.currency = self.currency;
277        character.standing.clone_from(&self.standing);
278        true
279    }
280
281    /// When this group was last taught, if ever.
282    #[must_use]
283    pub fn group_updated_at(&self, group: Group) -> Option<SystemTime> {
284        self.updated_at.get(&group).copied()
285    }
286
287    /// Record that a group was just taught.
288    pub fn touch(&mut self, group: Group, at: SystemTime) {
289        self.updated_at.insert(group, at);
290    }
291
292    /// Has this group ever been taught?
293    #[must_use]
294    pub fn is_known(&self, group: Group) -> bool {
295        self.updated_at.contains_key(&group)
296    }
297
298    /// Groups that need a command run, given how old is too old.
299    ///
300    /// **A group with no timestamp is always stale**, which is what makes the
301    /// first login sync everything. `max_age` covers the other case: a group
302    /// taught six months ago describes a character who has trained since.
303    ///
304    /// Returns them in [`Group::ALL`] order, so a caller issuing the commands
305    /// sends them in a stable sequence and a replay is deterministic.
306    ///
307    /// # A clock that went backwards does not make data fresh
308    ///
309    /// `duration_since` fails when `now` precedes the stamp -- a corrected
310    /// system clock, or a file copied from another machine. That is treated as
311    /// **stale**, not as fresh: the alternative is trusting a timestamp we have
312    /// just proved is wrong.
313    #[must_use]
314    pub fn stale_groups(&self, now: SystemTime, max_age: std::time::Duration) -> Vec<Group> {
315        Group::ALL
316            .into_iter()
317            .filter(|group| {
318                self.group_updated_at(*group)
319                    .and_then(|at| now.duration_since(at).ok())
320                    .is_none_or(|age| age > max_age)
321            })
322            .collect()
323    }
324
325    /// Can this snapshot be believed?
326    ///
327    /// Only when it was written by **this exact** schema version. Not `>=`: a
328    /// file from a newer version was written by a classifier this build does
329    /// not have, and reading its fields as if they meant what they mean here is
330    /// the same error as reading an older one.
331    #[must_use]
332    pub const fn is_current(&self) -> bool {
333        self.schema_version == SCHEMA_VERSION
334    }
335
336    /// Does this snapshot describe the character who just logged in?
337    ///
338    /// **Both halves, and the instance is the one that gets forgotten.** Two
339    /// characters of the same name on Prime and Platinum are different people
340    /// with different skills; loading one into the other would look like a
341    /// character who had silently lost training.
342    ///
343    /// Case-insensitive on the name because the wire is not consistent about
344    /// it -- `<playerID>` and the `Name:` line have differed -- and a store
345    /// that missed on case would silently start the character over.
346    #[must_use]
347    pub fn describes(&self, instance: &str, character: &str) -> bool {
348        self.instance.eq_ignore_ascii_case(instance)
349            && self.character.eq_ignore_ascii_case(character)
350    }
351}
