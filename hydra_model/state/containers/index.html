Which container holds what, and which weapon comes to hand.

Two lists the game keeps for you, taught by stow list and ready list and by the one-line confirmations that follow a stow set or ready.

§Patterns match the prose, not the markup

Each line names its container or item as a link. ChunkLine::links yields LinkKind::Exist typed, so a pattern here only has to say which slot a line is about; nothing re-tokenizes <a exist= noun=>.

§One store-mode, two spellings

The two messages that teach the store-mode disagree about its wording:

Taught by“wear it if you can” is spelled
ready listworn if possible, stowed otherwise
store setworn if possible and stowed if not

Same state, two spellings. Kept as a raw string, a consumer comparing it would get a different answer depending on which message happened to teach it last. The sheath spelling splits the same way – put in secondary sheath against stored in your secondary sheath. StoreMode reads both and stores one value, so the question “will this be worn?” has one answer.

§What is deliberately NOT here

Re-checking every held id against the inventory, and clearing the checked flag if one has gone, is a cache-coherence check, and it belongs to whoever owns inventory – not to a record of what the game said. Containers’s checked flag reports whether the list was ever taught; a consumer that needs “and the items still exist” asks inventory, which is the layer that knows.
