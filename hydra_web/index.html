Crate hydra_web 

Source
Expand description

Hydra’s web page: the hub and each character, served to the home network, for a phone, a tablet or another computer’s browser.

The page is a frontend beside the window, over the same board ([Sessions]): the same characters, each shown from its seat’s story. It is served while the window’s Web page setting is on, on its port, and moved or stopped the moment that changes (serve). A device plays only once it has said the pairing (pairing), which is in the address the hub shows. While it is served it is announced on the home network (bonjour), so the HydraFE app lists this computer.

The page’s files are plain HTML, CSS and JavaScript modules built into Hydra (assets/): nothing to build, nothing fetched from elsewhere.

Modules§

client
One page on the socket: paired first, then shown the hub or a character, and what it asks done.
follow
A page following a character’s story, and its streams: which of their lines the page has, and what to send it next.
highlights
The highlights on the page: each listed with what the page edits of it, and the page’s changes made as the window’s editor makes them, at once to every story and to the file with the next batch of saves.
http
One connection to the page’s server: a request for one of the page’s own files, answered and closed, or the page’s socket.
injuries
The injuries on the page: the window’s doll, its body drawn plainly with a dot on each hurt part ([hydra_ui::injuries]). The body is sent once, when a character is shown; what each part shows comes with the view.
inventory
The inventory on the page: the whole tree the game’s inventory manager gave (.inventory), as the window’s Inventory panel shows it, each item with what can be done with it. What an act sends is made here ([hydra_ui::inventory::Act]), never by the page.
pairing
The pairing: a secret kept in the data folder, which a device must say before the page’s socket answers it. It is in the address the hub shows, after the #, which a browser never sends to a server; the page keeps it, so a device pairs once. A new secret is made only when there is none, so a device stays paired from one run to the next.
phone
What a phone keeps as its own – its buttons, its wheel, how its page is laid out – copied to this computer and back, so another phone, or the same one on the phone’s own Hydra, can take it up. Each kind is one JSON file in the data folder’s phone/, written as the page sends it and read back as it asks; the page shows when each side last changed, and the player chooses the direction. Nothing is copied unasked.
tasks
The tasks on the page: the bounty, in brief and in the game’s own words, and the objectives the game has stated, as the window’s Bounty and Objectives widgets show them.
wire
What crosses the page’s socket, as JSON: each message an object whose t names it.
workspace
Each character’s workspace on the web page – where its modules sit, and how big – kept in the data folder, so every device and browser that shows the character finds it as last left.

Functions§

accept
Answer each connection to listener, until the listener fails. A connection that fails on its way in is passed over.
serve
Serve the page while it is wanted, on the port it is wanted on, to the home network; the pairing kept in data. Where it is, or why it is not, is told to the board for the hub. Returns when the board is gone.
serve_to
serve, to the devices reach says.
